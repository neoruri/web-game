## 2. `defs` 수정 — run 행은 걷기이고, 6프레임 중 4개만 쓴다

`src/main.js:1025` 근처.

### 지금
```js
run: { row: 1, frames: 6, fps: 12, loop: true, skip: 1 },
```

### 이렇게
```js
run: { row: 1, frames: 6, fps: 12, loop: true, order: [0, 1, 3, 5] },
```

`skip: 1` 을 **없앤다.** 새 시트는 0번 열부터 유효하다.
애니 키 이름은 `run` 그대로 둔다 — 호출부가 여럿이라 이름만 바꾸면 손댈 곳이 는다.
**내용이 걷기일 뿐이다.**

`order` 는 **행 안의 열 번호(0부터)** 다. 사람이 세는 번호로는 `1,2,4,6` 이다.

### 왜 걷기인가
달리기를 20번 가까이 실패했다. 마지막 원인은 **보폭이 너무 커서** 발이 바닥에
안 붙어 보인 것이었다. 걷기로 바꾸면서 "항상 한 발은 바닥에 닿아 있을 것" 을
조건으로 걸었고, 조립 후 실측에서 **떠 있는 프레임이 0개** 가 됐다.

### 왜 4개만 쓰나
시트 6프레임의 보폭(앞발↔뒷발 거리 ÷ 키):

```
열        0    1    2    3    4    5
보폭%     0   32   28   15   22   29
```

열 2·4 는 열 5·3 과 보폭이 거의 겹친다(28≈29, 22≈15 방향). 다 넣으면 같은
자세가 두 번 지나가서 걸음이 뭉갠다. `[0,1,3,5]` 는 `0 → 32 → 15 → 29` 로
**모음 → 크게 → 중간 → 크게** 가 되어 걸음마다 리듬이 선다.

열 2·4 는 시트에 남겨둔다. 나중에 6프레임으로 늘릴 여지다.

### fps 를 12 로 두는 이유 — 발 미끄러짐

4프레임이라 사이클이 짧다. 한 사이클에 걸음 2번이 들어가므로:

```
 fps   한 사이클   이동거리   걸음당    보폭 대비
  10     0.400s     40.0px   20.0px     1.11
  11     0.364s     36.4px   18.2px     1.01   ← 이론상 최적
  12     0.333s     33.3px   16.7px     0.93   ← 채택
  14     0.286s     28.6px   14.3px     0.80   ← 발이 20% 끌린다
```

화면상 최대 보폭 17.9px(셀 32.6px × 0.55), 이동속도는 `config.player.speed` 100px/s
기준이다. 1.00 이 안 미끄러지는 값이다. 11 이 가장 정확하지만 12 와 눈으로
구분이 안 되고, 12 는 다른 애니와 같은 값이라 맞춰 둔다.

> ⚠️ `config.player.speed` 를 바꾸면 이 비율이 깨진다.
> 속도를 올리면 fps 도 같이 올려야 한다 — `fps ≈ 4 × speed / (2 × 17.9)`.

### `generateFrameNumbers` 는 배열을 받는다
```js
for (const key in defs) {
  if (this.anims.exists(key)) continue
  const d = defs[key]
  const rowStart = d.row * 8
  this.anims.create({
    key,
    frames: d.order
      // ★ 임의 순서 — frames 옵션에 배열을 넘기면 그 순서로 재생된다
      ? this.anims.generateFrameNumbers('archer', {
          frames: d.order.map((c) => rowStart + c),
        })
      : this.anims.generateFrameNumbers('archer', {
          start: rowStart + (d.skip || 0),
          end: rowStart + d.frames - 1,
        }),
    frameRate: d.fps,
    repeat: d.loop ? -1 : 0,
  })
}
```

## 3. 활 — 별도 스프라이트, **플레이어 뒤**

### 왜 분리했나
확정 시안이 활을 캐릭터 옆에 별도 오브젝트로 그려왔고 손은 비어 있다.
그대로 가는 게 유리하다.

- 활을 손에 들면 **팔이 스윙을 못 한다.** 이전 시안들이 활을 앞으로 뻗고 있어서
  달리기 자세 자체가 성립하지 않았다
- run 6프레임마다 활을 다시 그릴 필요가 없다 → 형태가 프레임마다 안 흔들린다
- 각도를 코드로 준다. 등에 비스듬히 멘 배치가 프레임마다 자연스럽게 바뀐다

### 로드
```js
this.load.image('playerbow', '/sprites/dungeon/deliverables/player_bow.png')
```

### 생성 — `playerSprite` **보다 먼저** worldLayer 에 넣는다
```js
// ⚠️ 순서가 중요하다. 먼저 add 해야 플레이어 **뒤**에 깔린다(등에 멘 배치).
this.bowSprite = this.add
  .image(this.player.x, this.player.y, 'playerbow')
  .setOrigin(0.5, 0.52)          // 활 중앙보다 살짝 아래가 손잡이
  .setScale(scale)               // 플레이어와 같은 scale
this.worldLayer.add(this.bowSprite)
// … 그다음에 playerSprite 를 만들고 add 한다
```

### 프레임별 오프셋 — **애니메이션마다 다르다**

idle 은 서 있고 run 은 팔이 크게 스윙한다. 손 위치가 달라서 같은 값을 쓰면
idle 에서 활이 몸에서 떨어져 보인다. 애니별로 나눈다.

```js
// [x, y, 각도(도)] × 시트 열.
//   y 는 **발끝(접지선) 기준**, 음수가 위. 파이프라인의 ANCHOR 와 같은 기준이다.
//   x 는 캐릭터 중심 기준, 양수가 앞(바라보는 쪽).
//   전부 애니 테스트에서 프레임마다 눈으로 맞춘 값이다.
const BOW_OFF = {
  idle: [
    [3, -40, 50],
    [6, -40, 50],
    [4, -41, 50],
    [4, -40, 50],
  ],
  run: [
    [6, -38, 45],   // 열0  PASSING  발 모음
    [6, -38, 45],   // 열1  CONTACT
    [6, -38, 45],   // 열2  (order 에서 미사용)
    [6, -38, 45],   // 열3  중간
    [6, -38, 45],   // 열4  (order 에서 미사용)
    [6, -38, 45],   // 열5  CONTACT 반대발
  ],
}
```

> idle 은 4프레임이라 배열도 4개다. run 6프레임 중 열 2·4 는 `order` 에서
> 안 쓰이지만, **인덱스가 어긋나지 않게 자리를 채워둔다.**
>
> run 은 여섯 열이 **전부 같은 값**이다(6, −38, 45). 걷기는 상체가 거의 안
> 흔들려서 — 실측 몸통 가로 진폭 2.3px(화면 1.3px) — 등에 멘 활이 프레임마다
> 움직일 이유가 없다. 각도를 프레임마다 바꿔 까딱이게 해봤는데 오히려 활이
> 등에서 흔들려 보여서 45° 고정으로 되돌렸다.
>
> 즉 run 은 `table[col]` 결과가 어느 열이든 같다. 그래도 배열로 두는 건
> back_run·attack 이 들어올 때 열마다 달라질 수 있기 때문이다. 구조는 유지한다.

### 매 프레임 갱신

```js
// updatePlayerAnim 뒤나 update 말미에 둔다.
const table = BOW_OFF[this.animKey]
if (table) {
  const col = this.playerSprite.frame.name % 8   // 행 안의 열 번호
  const off = table[col] || table[0]             // 아직 없는 애니는 첫 값으로 버틴다
  const dir = this.playerSprite.scaleX < 0 ? -1 : 1
  this.bowSprite.setPosition(
    this.player.x + off[0] * scale * dir,
    this.player.y + off[1] * scale
  )
  this.bowSprite.setScale(scale * dir, scale)
  this.bowSprite.setAngle(off[2] * dir)
  this.bowSprite.setVisible(this.animKey !== 'death')
} else {
  // back_run / hit / death 는 아직 값이 없다. 활을 감춘다.
  this.bowSprite.setVisible(false)
}
```

> `dir` 을 x·각도에 **둘 다** 곱해야 왼쪽을 볼 때 활이 반대로 눕지 않는다.
> `BOW_OFF` 에 없는 애니는 활을 감춘다 — 엉뚱한 위치에 붙는 것보다 낫다.

## 4. 확인할 것

```
npm run build
```

그리고 게임을 띄워서 눈으로:

1. **걸을 때 활이 등에서 떨어져 보이지 않는가** — 오프셋이 어긋나면
   BOW_OFF 값을 조정한다. `tools/sprites/_anim_test.html` 에서 슬라이더로 다시 뽑으면 된다
2. **좌우로 방향을 바꿔도 활이 등 쪽에 붙어 있는가**
3. **발이 바닥에서 미끄러지지 않는가** — 미끄러지면 fps 를 11 로 내린다.
   제자리걸음처럼 보이면 13 으로 올린다
4. **상체가 앞뒤로 출렁이지 않는가** — 출렁이면 조립 단계 문제다.
   `python3 tools/sprites/apply_walk_gpt.py --sway 0.10 --write` 로 줄이고 다시 커밋
5. 죽을 때 활이 남아 있지 않은가

## 7. 8/19 개정에서 실제로 바뀐 것

### 7-1. 소스를 GPT 로 바꿨다
같은 프롬프트를 Gemini 와 GPT 에 각각 돌려 나란히 재생해보고 골랐다.
보폭(앞발↔뒷발 ÷ 키):

```
Gemini   21  16   0  20  24  22    ← 0 하나 빼면 전부 ~20. 다리만 좌우로 바뀐다
GPT       0  33  29  15  23  31    ← 0~33 을 오르내린다
```

Gemini 는 여섯 중 다섯이 같은 보폭이라 **걸음의 리듬이 없다.** 순서를 720가지
전부 돌려도 못 고쳤다(484 → 246 이 한계). 발 각도 변화폭도 2.6 대 3.8 로
GPT 가 뒤꿈치 착지와 발끝 밀기를 구분해서 그렸다.

### 7-2. 조립할 때 세 가지를 맞췄다

`tools/sprites/apply_walk_gpt.py` 가 전부 자동으로 한다. 손으로 만지지 말 것.

**색** — GPT 가 같은 캐릭터를 갈색으로 그렸다. 갑주 평균 RGB 실측:
```
gem_N2_c(기준)  [64.2 66.5 56.1]
idle 행         [67.7 69.4 57.8]   기준과 3.5 이내
GPT walk 원본   [63.1 56.8 52.5]   G 가 9.7 낮다
GPT walk 보정후 [63.8 65.8 55.5]
```
idle 과 walk 이 번갈아 재생되므로 이걸 안 맞추면 캐릭터가 바뀐 것처럼 보인다.

**발광** — 원본 1.85% 라 idle(6.36%) 옆에 두면 룬이 꺼진 것처럼 보였다.
목표값을 고정하지 않고 **idle 행에서 직접 재서** 맞춘다.

**가로 위치** — 이게 제일 컸다. 프레임을 bbox 중심으로 놓고 있었는데,
bbox 는 뻗은 다리까지 포함하고 다리는 몸통과 반대로 흔들린다. 그래서
bbox 중심은 고정돼 보이는데 **몸통이 밀려난다**:
```
열        0     1     2     3     4     5    진폭
bbox중심  47.5  47.0  47.0  48.0  47.5  47.5   1.0
엉덩이x   49.5  45.5  53.9  48.0  52.4  52.2   8.5   ← 상체가 출렁였다
```
정렬 기준을 **몸통(어깨~엉덩이)** 으로 바꾸고 리듬용으로 20% 만 남겼다.
결과 진폭 2.3px(화면 1.3px), 인접 최대 이동 7.5 → 2.2px.

### 7-3. 최종 실측
```
접지 편차 0px      키 편차 2px (1.9%)     몸통 가로 진폭 2.3px
떠있는 프레임 없음  [0,0,0,0,0,0]
사용 보폭 흐름     0 → 32 → 15 → 29      (열 0,1,3,5)
```
