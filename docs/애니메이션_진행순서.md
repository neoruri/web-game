# 플레이어 애니메이션 — 진행 순서

> 캐릭터 확정: **`tools/sprites/cands/gem_N2_c.png`** (2026-08-18)
> 살아있는 마법 궁수 · 후드(얼굴 그림자) · 다리 노출 · 활은 별도 오브젝트

---

## 0. 순서

```
1. Gemini 새 대화 → M1_idle 요청 (gem_N2_c.png 첨부)
                  → tools/sprites/player_strips/idle.png 로 저장
2. ★ 또 새 대화   → M2_run 요청 (gem_N2_c.png 첨부)
                  → tools/sprites/player_strips/run.png 로 저장
3. 알려주시면 조립 + 검증 + 애니 테스트 페이지를 만든다
```

**2번에서 반드시 새 대화를 열 것.** 같은 대화에서 이어 요청하면 앞의 결과를
물려받는다. run 을 4+4 로 나눠 요청했을 때 후반부가 전반부와 실루엣 차이
**0.1~1.5%** 로 사실상 동일하게 나온 적이 있다.

## 1. 파일

### 요청문 (내용 전체를 복사해서 한 메시지로)
```
docs/요청문_애니메이션/M1_idle_4frames__attach_gem_N2_c.txt
docs/요청문_애니메이션/M2_run_8frames__attach_gem_N2_c.txt
```
파일명의 `__attach_` 뒤가 **첨부할 이미지**다. 둘 다 `gem_N2_c.png` 를 첨부한다.

### 결과 저장 위치 — 파일명을 정확히 지킬 것
```
tools/sprites/player_strips/idle.png
tools/sprites/player_strips/run.png
```
> `build_player_sheet.py` 는 **정확 일치**로 찾는다. 부분 일치를 쓰면
> `run` 이 `backrun` 까지 잡아서 못 쓴다. `idle_final.png` 같은 이름은 안 된다.

한 번에 잘 안 나오면 `idle_a.png`, `idle_b.png` 로 여러 장 받아두고
고른 것을 `idle.png` 로 이름만 바꾸면 된다.

## 2. 이번 요청문에서 달라진 것

### ★ 활을 그리지 말라고 명시했다
`gem_N2_c` 는 활이 **캐릭터 옆에 별도 오브젝트로** 그려져 있다. 손은 비어 있다.
그대로 간다 — 활은 게임 코드에서 **별도 스프라이트 레이어**로 붙인다.

이유가 두 개다.
- 활을 손에 들면 **팔이 스윙을 못 한다.** 이전 시안들이 활을 앞으로 뻗고 있어서
  달리기 자세 자체가 불가능했다
- 프레임마다 활을 다시 그릴 필요가 없어진다. 활 형태가 흔들리지 않는다

첨부 이미지에 활이 보이므로, 요청문에 **"Do NOT draw the bow, hands are EMPTY"**
를 대문자로 박아뒀다. 이 문장을 지우지 말 것.

### 프레임별 보폭을 숫자로 지정했다
```
f1 13%   f2 31%   f3 50%   f4 18%      (몸높이 대비 두 발 사이 거리)
f5~f8 = f1~f4 의 좌우 교대
```
지금까지 한 번도 못 했던 지시다. **다리가 안 보이는 캐릭터였기 때문**이다.
이제 다리가 드러나므로 보폭으로 달리기를 표현할 수 있다.

### 세로 반동을 명시적으로 눌렀다
`머리 상하 변동 3% 이내`, `한 발은 항상 땅 근처`, `DO NOT make him jump`.
이전에 공중 프레임을 요구했다가 **"작게 점프해서 탁 떨어지는"** 결과가 나왔다.
레퍼런스 실측에서도 발끝 y 변동이 0 이었다. 달리기는 **보폭**으로 표현된다.

### 프레임 간격 40px
`multishot` 5·6번, `death_a` 4개 중 2개가 붙어서 분리에 실패한 적이 있다.

## 3. 받은 뒤 자동으로 처리되는 것

`build_player_sheet.py` 가 한다. 손댈 필요 없다.

```
1. 초록 언매팅        단순 임계값은 실패했다 (얇은 활이 초록으로 남았다)
2. AI가 그린 바닥선 제거   no floor 를 써도 매번 그려온다
3. 런렝스 프레임 분리      균등 분할 불가. AI는 간격을 못 맞춘다
4. 애니별 공통 배율        프레임마다 따로 맞추면 커졌다 작아진다
5. 발끝 y=108 정렬        애니 단위 오프셋이라 공중 프레임 높이차는 보존된다
6. 발광색 #e05cff 보정    실측이 탁하게 나온다
7. 밑단 발광 자동 부착     목표 14.4% 를 이분법으로 맞춘다
```

## 4. 남아 있는 문제 두 개 (후처리로 해결, 재요청 불필요)

### 몸통 명도 62.8 → 목표 50~58
바닥이 42.3 인데 캐릭터가 밝아서 붕 떠 보인다.
프롭 8종 때와 같이 **감마 이분법**으로 목표 명도에 맞춘다.

### 다리대비 3.8 → 목표 12 이상
`gem_N2_c` 는 갑주가 다리까지 촘촘해서 다리와 몸통 명도가 거의 같다.
64px 에서 하반신이 한 덩어리로 뭉칠 위험이 있다.
조립할 때 **하반신 구간만 명도를 올려서** 분리를 만든다.

> 둘 다 조립 단계에서 처리하므로, 지금 다시 요청할 필요는 없다.

## 5. 규격 (`main.js` 와 일치 — 바꾸면 코드 수정 필요)

```

행: 0 idle / 1 run / 2 back_run / 3 attack / 4 multishot / 5 hit / 6 death
프레임: 4 / 8 / 8 / 6 / 6 / 3 / 8
fps:  6 / 12 / 12 / 14 / 14 / 10 / 10
발광색 #e05cff (색조 292° — main.js 에서 280~339° 가 비어 있다)
배경 초록 #00FF00 (마젠타는 못 쓴다. 캐릭터 발광이 자마젠타다)
```
