# 변경내역 — 룬 등급 + 랜덤 롤 + 3슬롯 + 랜덤 획득 UI

> 작성: 2026-08-07 · 기획·에셋 채팅(Cowork)에서 **직접 코드 반영함**
> 코드 채팅은 이 문서를 먼저 읽고 이어서 작업할 것. 커밋 전 **Windows에서 `npm run build` 확인 필요.**

## 요약 — 무엇이 바뀌었나

| 항목 | 이전 | 지금 |
|---|---|---|
| 룬 데이터 | 문자열 `'damage'` | **인스턴스 `{id, tier, v}`** |
| 등급 | 없음 | **일반/레어/에픽** (확률 62/29/9%, 후반 상향) |
| 수치 | 고정(+20% 등) | **랜덤 롤** (예: 데미지 10~45%) |
| 슬롯 | 스킬당 1개 | **스킬당 3개** (`RUNE_SLOTS`) |
| 획득 흐름 | 3개 중 1택 → 스킬 | **랜덤 1개 → 스킬 1탭**(시안 B) |
| 드랍원 | 보스만 | 보스(모달) + **일반몹 1%(자동 장착)** |
| 한 판 룬 수 | 0.91개 | **중앙값 7개** |

## 1. `src/main.js`

### 1-1. 룬 정의 교체
```js
const RUNE_TIERS = { 1:{name:'일반',...,chance:.62}, 2:{name:'레어',...,.29}, 3:{name:'에픽',...,.09} }
const RUNES = {
  damage:     { range:{1:[10,18],2:[20,30],3:[32,45]}, fmt:v=>`피해 +${v}%` },
  pierce:     { range:{1:[1,1],  2:[1,2],  3:[2,3]},  int:true },
  projectile: { range:{1:[1,1],  2:[1,2],  3:[2,2]},  int:true },
  cooldown:   { range:{1:[8,14], 2:[16,22],3:[24,30]} },
  burn:       { range:{1:[18,28],2:[30,42],3:[45,60]} },  // 도트 %/초
}
const RUNE_SLOTS = 3
```
- `rollRuneTier(elapsed)` — 시간이 지나면 상위 등급 확률이 완만히 상승(최대 +18%p)
- `rollRune(id, elapsed, tier?)` — 수치를 굴려 인스턴스 생성
- `runeLabel(r)` / `runeDesc(r)` — 표시용

### 1-2. 슬롯 = 배열
```js
this.runeSlots[skillId] = [null, null, null]   // RUNE_SLOTS 칸
this._pendingRunes = []                        // 획득 대기 큐
```

### 1-3. 획득 흐름 (시안 B)
- `grantRune(boss)` — 랜덤 룬을 굴려 **큐에 넣음**. 보스는 등급 보정(+120초 상당)
- `openRuneDrop()` — 큐 맨 앞 룬을 보여주고 **스킬만 선택**(룬 선택 단계 없음)
- `onRuneEquip(skillId, slotIdx)` — slotIdx < 0 이면 **빈 슬롯 자동**, 꽉 찼으면 첫 칸 교체
- `autoGrantRune()` — **일반몹 드랍용.** 모달 없이 빈 슬롯에 자동 장착 + 팝업.
  빈 슬롯이 전부 없으면 드랍을 버린다(전투 흐름 우선)
- `spawnRuneToast()` — 데미지 숫자 팝업을 재사용해 `🔥 화상 · 레어` 표시

### 1-4. 기타
- `spawnPopup(x,y,amount,crit,color)` — **color 인자 추가**(문자열 텍스트도 허용)
- `damageEnemy`의 `burn`이 **불린 → 도트 %/초 수치**로 변경(`true`면 기본값 폴백)
- 보스 처치부: `_pendingRune = true` → `grantRune(true)`
- 일반몹 처치부: `cfg.rune.normalDropChance` 확률로 `autoGrantRune()`

## 2. `src/progression.js`

### `aggregateRunes(slots)` 신규 (export)
슬롯 배열 → 종류별 합계. **하위 호환**: 문자열/단일 객체도 처리.

| 룬 | 스택 규칙 |
|---|---|
| damage / pierce / projectile | **합산** |
| cooldown | 합산, **`RUNE_CDR_CAP = 45%` 캡** |
| burn | **최댓값만** (도트 중첩은 과함) |

적용부(기본 활 + 각 스킬)를 배열 기준으로 교체. 쿨타임은 기존 `minSkillCooldown` 하한도 유지.

### 단위 검증 (통과)
```
데미지 15+25+40      → 80%
쿨감 30×3            → 45% (캡)
화상 20/55           → 55 (최댓값)
문자열 'damage'      → 20 (레거시 폴백)
```

## 3. `src/sim.js` — 동기화

- `runeSlots`를 3칸 배열로, `simRollRune()`로 등급·수치 롤(**main.js와 같은 값 유지 필수**)

- 일반몹 드랍(`cfg.rune.normalDropChance`)도 반영
- `state.runesGained` / 결과에 `runesGained` 추가 → **룬 획득 수를 측정 가능**
- `burn` 수치화 반영

> ⚠️ `SIM_RUNE_RANGE`·확률(0.09/0.29)·`RUNE_SLOTS`는 main.js와 **이중 선언**이다.
> 값을 바꿀 때 반드시 두 파일 모두 수정할 것.

## 4. `src/rune-screen.js` + CSS — 시안 B UI

- 흐름: 큰 아이콘으로 **획득 연출**(등급색 테두리 + 굴려진 수치) → **스킬 1탭**

### ⚠️ 남은 문제 — 31%의 판이 룬 0개

- 첫 보스만 더 앞당기기(예: 40초)
- 레벨 3 도달 시 룬 1개 지급(모두가 시스템을 경험)
- 초반 스폰 압박 완화

## 6-b. 2차 변경 — 자동 장착 폐기 → **룬 가방 + 레벨업 통합 화면**

### 왜 바꿨나
자동 장착은 전투를 끊지 않는 대신 **"어떤 룬을 어디에 넣을까"라는 선택의 재미를 없앴다.**
그렇다고 획득할 때마다 모달을 띄우면 한 판 7번 끊긴다.
→ **이미 게임이 멈추는 레벨업 화면**(한 판 평균 17~19회)에 얹어 **추가 인터럽션 0**으로 해결.

### 획득 경로 정리
| 드랍원 | 처리 | 이유 |
|---|---|---|
| **보스** | 즉시 모달(스킬 1탭) | 한 판 1~2회, 하이라이트 순간 |
| **일반몹** | **가방에 보관 + NEW 배지 + 토스트** | 잦으므로 전투를 끊지 않는다 |

### `src/main.js`
- `autoGrantRune()` **삭제** → `bagGrantRune()` 신규: 룬에 `isNew=true`를 달아 `this.runeBag`에 push + 토스트
- `this.runeBag = []` 신규 (판마다 리셋)
- `getRuneState()` — 레벨업 화면에 넘길 `{ bag, skills }`. 가방 항목엔 표시용
  `icon/tierName/tierColor/label/desc/short`가 포함된다
- `equipFromBag(bagIdx, skillId, slotIdx)` — 장착. **기존 룬이 있으면 교체하고 그 룬은 가방으로 복귀**
- `RUNES[*].shortFmt` 추가 — 가방 칸에 넣을 짧은 표기(`+41%`, `36%/s` 등)
- 레벨업 화면 생성 시 `getRuneState` / `onEquipFromBag` 콜백 전달

### `src/levelup-cards.js` — 통합 화면으로 전면 교체
**탭 없음.** 한 스크롤에 위→아래로 세 구획:
```
① 성장 카드(가로 3장)  ② 룬 가방(4열 그리드)  ③ 스킬 슬롯(스킬별 3칸)
```
- **카드 1장 선택은 필수** → 고르면 하단 "계속" 활성
- **카드를 골라도 화면이 닫히지 않는다.** "계속"을 눌러야 카드가 적용되고 닫힌다
  → 카드와 룬을 **한 번에** 처리 가능
- **룬 장착은 선택사항**. 관심 없으면 `카드 1탭 + 계속 1탭`으로 종료
- 가방 룬 탭 → 슬롯이 초록(`target`)으로 표시 → 슬롯 탭하면 장착(즉시 갱신)
- **비교 화살표** `compare()`: 장착중인 **같은 종류** 룬의 최고값과 비교해 ▲/▼ 표시
  (같은 종류가 없으면 표시 없음)
- 카드 선택 후에도 하단에 `아직 NEW 3개` 를 남겨 룬을 놓치지 않게 함
- 계약 변경: `createLevelupScreen({ onPick, getRuneState, onEquipFromBag })`

### `src/levelup-cards.css`
`.lv-scroll` `.lv-foot` `.lv-sechd` `.lv-cards`(가로 3장) `.lv-bag` `.lv-item`
`.lv-new` `.lv-cmp` `.lv-srow` `.lv-slot` 등 추가. 패널에 `max-height: 92vh` + 내부 스크롤.

### 시뮬 재검증 (90판)
생존 중앙값 **210s** · 평균 레벨 **17.3** · 보스 **1.51** — 이전과 동일 수준(밸런스 영향 없음).
가방 방식은 **시각/조작 변경**이라 시뮬(봇 자동장착)에는 영향이 없다.

> ⚠️ `sim.js`는 봇이 즉시 자동장착하는 모델을 유지한다(가방 개념 없음).
> 밸런스 상한을 보는 용도이므로 의도된 단순화다.

## 7. 플레이 테스트에서 확인할 것
1. 룬 획득 모달이 **1탭으로 끝나는지**, 초록 추천이 도움이 되는지
2. **에픽 룬을 먹었을 때 티가 나는지**(수치 차이 체감)
3. 3슬롯이 **너무 강한지** — 특히 쿨감 3개(45% 캡) + 데미지 3개
4. 일반몹 자동 장착 팝업이 **눈에 들어오는지 / 방해되지 않는지**
5. 빈 슬롯이 꽉 찬 뒤 일반몹 드랍이 버려지는 게 아깝게 느껴지는지
   (아깝다면 "가방" 도입 or 약한 룬 자동 교체 검토)
