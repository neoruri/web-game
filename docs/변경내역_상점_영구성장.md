## 1. 흐름

```
사망 → 결과 화면 → [🛒 상점] → 강화 구매 → [돌아가기] → 결과 화면 → [다시 하기]
```

**상점은 결과 화면을 닫지 않는다.** 위에 겹쳐 열리고 닫으면 결과로 돌아온다.
사고 나서 바로 "다시 하기"를 눌러 효과를 시험하는 흐름이 되게 했다.

사망 직후를 고른 이유 — 이미 게임이 멈춰 있고, 방금 번 골드가 눈앞에 있고,
재시작 직전이다. 별도 메뉴로 빼면 아무도 안 들어간다.

## 2. 스탯 5종 (요청대로)

| 스탯 | 레벨당 | 적용 지점 |
|---|---|---|
| ⚔️ 공격력 | +1% | 기본 활 + 모든 스킬 피해 |
| ❤️ 최대 체력 | +1% | 시작 체력 |
| ✚ 체력 회복 | **+0.1/초** | 초당 자동 회복 |
| 👟 이동 속도 | +1% | 걷는 속도 |
| 🪙 골드 획득 | +1% | 획득 골드량 |

### ⚠️ 회복만 절대값인 이유
`체력 회복`을 퍼센트로 만들면 **아무 효과가 없다.** 기본 회복량이 `0`이기 때문이다
(능력치 시스템이 보류 상태라 `tierBonuses.regen`이 항상 0). `0 × 1.05 = 0`.
→ 기본값이 0인 스탯은 반드시 **flat**으로 줘야 한다. `UPGRADES.regen.flat = true`.

## 3. 가격 — 레벨마다 2배 (요청대로)

`가격 = 10 × 2^(현재레벨)`

| 레벨 | 효과 | 가격 | 누적 | 필요 판수(60골드/판) |
|---|---|---|---|---|
| 1 | +1% | 10 | 10 | 0 |
| 3 | +3% | 40 | 70 | **1** |
| 5 | +5% | 160 | 310 | 5 |
| 8 | +8% | 1,280 | 2,550 | 43 |
| 10 | +10% | 5,120 | **10,230** | **171** |

**가격 곡선은 좋다.** 초반 3레벨이 70골드(한 판)라 첫 보상이 즉시 오고,
2배 곡선이라 **별도 상한 없이 자연히 상한이 생긴다.**
5스탯 전부 Lv5 = 1,550골드(약 25판), 전부 최대 = 51,150골드.

## 4. 🔴 밸런스 경고 — `per: 1%` 는 너무 약하다

가격은 요청대로 넣었지만, 효과 크기를 계산해보면 문제가 보인다:

```
5판을 해도  공격력 +5%   → 기본 피해 20 → 21
171판을 해도 공격력 +10%  → 기본 피해 20 → 22
```

**플레이어가 차이를 느끼지 못한다.** 참고로 뱀서의 Might 파워업은
레벨당 **+5%**, 5레벨에 +25% 다.

골드 획득은 특히 약하다 — **+1% 는 판당 60골드에서 0.6골드**다.

### 권장
`src/meta.js` 의 `per: 1` → **`per: 3~5`**
→ Lv5 에 +15~25% 가 되어 체감이 생긴다. 가격 곡선은 그대로 두면 된다.

`per` 한 곳만 바꾸면 UI 표기·가격·저장이 전부 따라온다(계산이 한 군데에 모여 있다).

> 스펙대로 `1`로 넣어뒀다. 실제로 플레이해서 체감을 확인한 뒤 올리시는 게 맞다고 본다.

## 5. 구현 구조

### `src/meta.js` — 순수 로직 (UI 없음)
`UPGRADES` 정의 · `costOf()` · `valueOf()` · `spentOn()` · `metaBonuses()` ·
`loadMeta()/saveMeta()` · `buyUpgrade()`

- 저장 키 `wg_meta_v1` — **골드(`wg_gold_v1`)와 분리.**
  나중에 "업그레이드만 초기화" 같은 조작이 필요할 수 있다
- 손상된 저장값은 `0 ~ max` 로 clamp — 값이 깨져도 게임이 안 죽는다

### `src/progression.js` — 7번째 파라미터
```js
deriveStats(cfg, attr, skills, specs, cardBonus, runeSlots, meta)
```
메타 배율을 **가장 마지막에** 곱한다(런 내 성장과 독립적으로 읽히게).
골드 배율은 `s.goldMul` 로 stats 에 실었다 — 전투 수치는 아니지만
한곳에서 읽게 두면 실수가 줄어든다.

> ⚠️ **`recompute()` 에도 `metaBonus` 를 넘겨야 한다.** 빼먹으면 레벨업이나
> 룬 장착으로 재계산될 때마다 **상점 강화가 사라진다.** 가장 놓치기 쉬운 버그라
> 정적 점검에 "deriveStats 호출 수 == metaBonus 전달 수" 항목을 넣었다.

### 골드 배율은 소수 누적
```js
this._goldAcc += this.goldMul     // 내부는 소수
this.gold = Math.floor(this._goldAcc)  // 표시는 정수
```
동전 **개수**를 늘리는 방식은 +10% 에서 대부분 +0개가 되어 체감이 없다.

### 상점 열린 동안 재시작 차단
결과 화면이 열려 있으면 탭·스페이스로 재시작되는데, 상점을 겹쳐 열면
쇼핑 중 실수로 새 판이 시작된다 → 두 경로 모두에 `!shop.isOpen` 가드 추가.
