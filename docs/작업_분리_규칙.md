# 두 채팅 작업 분리 규칙

> 이 프로젝트는 **두 개의 AI 채팅**이 같은 폴더(`E:\claude\web-game`)를 만진다.
> - **기획 채팅** (Cowork / Claude) — 설계·에셋·밸런스 시뮬·문서·UI 오버레이
> - **코드 채팅** (Codex) — 빌드·커밋·핵심 로직·리팩터
>
> **두 채팅은 대화 내용을 공유하지 않는다. 공유 수단은 git과 이 폴더의 파일뿐이다.**
> 이 문서는 그 전제 위에서 사고를 막기 위한 규칙이다.

---

## 0. 왜 규칙이 필요한가 — git이 못 막는다

두 채팅이 **같은 작업 트리**를 쓰면 merge 단계가 없다.
A가 `main.js`를 고치고 커밋 안 한 상태에서 B가 같은 파일을 고치면
git은 충돌을 **알려주지 않고** 그냥 마지막 내용이 남는다.

```
브랜치가 다르면      → git이 충돌을 잡아준다 ✅
같은 작업 트리면     → 조용히 덮인다 ❌   ← 지금 상태
```

→ 분리는 **공간(worktree)** 또는 **시간(턴 교대)** 중 하나로 강제해야 한다.

---

## 1. 파일 소유권 (기본 규칙 · 비용 0)

| 영역 | 소유자 | 비고 |
|---|---|---|
| `src/main.js` | **Codex 전용** | 가장 크고 가장 자주 충돌. 기획 채팅은 직접 수정 금지 |
| `src/config.js` · `skilltree.js` · `progression.js` | **Codex** | 밸런스 수치는 기획이 값만 제안 |
| `src/*-screen.js` · `src/growth-ui.js` · `levelup-cards.js` | **기획** | HTML 오버레이 UI |
| `src/*.css` | **기획** | |
| `src/sim.js` | **기획** | 헤드리스 밸런스 시뮬 |
| `public/sprites/**` · `gen_*.py` | **기획** | 에셋 생성기 |
| `docs/**` | **기획** | Codex는 읽기만 |

**`main.js`가 핵심이다.** 기획 채팅이 `main.js`를 바꿔야 하면
직접 수정하지 말고 `docs/변경내역_*.md`에 **적용할 diff를 적어서** 넘긴다.

> ⚠️ 지금까지는 기획 채팅이 `main.js`를 직접 고쳐왔다. 충돌 위험 1순위.
> 이 규칙 시행 시점부터는 문서 경유로 바꾼다.

## 2. 턴 교대 (반드시)

작업을 **시작하기 전에** 양쪽 채팅 모두:

```bash
git status              # 깨끗해야 한다. 아니면 앞 작업이 안 끝난 것
git log --oneline -5    # 상대가 뭘 했는지 확인
```

작업을 **끝내면** 반드시 커밋한다. 미커밋 상태로 상대에게 턴을 넘기지 않는다.

```bash
npm run build           # ⚠️ Codex/윈도우에서만 가능 (기획 채팅은 리눅스 샌드박스)
git add . && git commit -m "[plan] ..." 
```

커밋을 못 할 상황이면 최소한 `git stash`로 작업 트리를 비운다.

---

## 3. 커밋 메시지 접두어

```
[plan]  기획 채팅(Cowork)이 만든 변경
[codex] 코드 채팅(Codex)이 만든 변경
```

`git log --oneline`만 봐도 누가 뭘 했는지 읽힌다.
(기존 `feat: ... (Codex 작업)` 방식을 규칙화한 것)

---

## 4. 상태 동기화 — `docs/다음_진행사항.md`가 단일 진실 소스

커밋할 때마다 그 문서 상단에 **3줄**을 남긴다.

```
- 2026-08-10 [plan] 결과 화면 + 스크롤 버그 수정 → 커밋 대기
  다음: 무한 난사 차단(쿨타임 하한 ≥ 지속+0.5s)은 Codex가 config/skilltree에서
```

**"현재 코드 상태"를 문서에 쓸 때는 반드시 파일을 다시 읽고 쓴다.**
(기억으로 쓴 탓에 "적이 원으로 그려진다" 같은 오기를 이미 두 번 냈다)

## 5. 완전 분리가 필요해지면 — git worktree

한 사람이 두 채팅을 **동시에** 돌리고 싶어질 때만 도입한다.

```bash
cd E:\claude\web-game
git worktree add ../web-game-plan -b plan
cd ../web-game-plan && npm install
```

- 기획 채팅 → `E:\claude\web-game-plan` (브랜치 `plan`)
- 코드 채팅 → `E:\claude\web-game` (브랜치 `main`)
- 합칠 때 `git merge plan` → **충돌이 git에 보인다**

**비용**: 폴더 2개, `npm install` 2번, Cowork에 새 폴더 재연결, 병합 작업 추가.
→ 현재 규모(개인 사이드 프로젝트, 턴 교대로 충분)에서는 **과하다.**
   §1+§2로 사고가 반복되면 그때 도입한다.

## 6. 창을 동시에 띄워두는 것 자체는 문제 없다

Cowork 창과 Codex 터미널은 별개 프로세스라 동시에 켜두는 데 제약이 없다.
**문제는 프로그램이 아니라 같은 폴더를 동시에 쓰는 것**이므로 §1·§2로 해결된다.

### 개발 서버(`npm run dev`)
- 코드 채팅에 시키면 **그 채팅의 자식 프로세스**로 돌아간다 → 창이 안 뜨고,
  그 터미널을 닫으면 서버도 죽는다
- 계속 켜두고 튜닝할 거면 **직접 cmd로 띄우는 쪽**이 낫다
  (탐색기 주소창에 `cmd` → `npm run dev`)
- 서버가 안 죽고 남으면 포트 5173이 점유돼 Vite가 조용히 **5174**로 올라간다.
  `netstat -ano | findstr :5173`로 확인

## 7. 정리 필요 — `pasted-text.txt`

리포지토리 루트에 `pasted-text.txt`(1,700줄+ 변경)가 추적되고 있다.
임시 붙여넣기 파일로 보인다. **삭제 + `.gitignore` 추가**를 권장.
매번 diff를 오염시켜 "무엇이 실제 변경인지" 읽기 어렵게 만든다.
