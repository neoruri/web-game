# 스프라이트 만드는 다른 길 — 3D 경유

> AI 로 프레임을 한 장씩 그리는 방식은 **20회 넘게 돌았는데 동작이 안 맞았다.**
> 근본 원인과 대안을 정리한다. 작성 2026-08-18.

---

## 0. 왜 지금 방식이 안 되는가

**AI 는 프레임을 한 장씩 독립적으로 그린다.** 각 장은 멀쩡한데 이어 붙이면
동작이 안 이어진다. 이번 run 하나에서만:

```
겹쳐서 나옴 → 잘라냄
6프레임만 나옴 → 8프레임은 캔버스에 물리적으로 안 들어감
f2·f5 가 정지 자세 → 재요청
f5 만 안 고쳐짐 → 또 재요청
보폭 79% vs 10% → 진폭이 안 맞음 → 또 재요청
속도 안 맞음 → fps 12 → 8 → 6 → 7
```

**보폭·무릎 높이·팔 각도를 매번 말로 지시해서 맞추는 구조**다. 한 프레임을
고치면 다른 프레임과의 관계가 또 어긋난다. 프레임이 늘수록 조합이 폭증한다.

애니메이터가 하는 일은 이게 아니다. **뼈대 하나를 움직여서 전 프레임을 한 번에
만든다.** 그러면 동작은 정의상 맞는다.

---

## 1. ⭐ 대안 — 3D 를 거쳐서 2D 스프라이트를 뽑는다

```
① 캐릭터 이미지 → 3D 모델        Meshy / Tripo (이미지 1장 → 3D, 무료 티어)
② 3D 모델 → 뼈대 붙이기          Mixamo (Adobe, 무료, 5분)
③ 애니메이션 고르기              Mixamo 라이브러리 (run/idle/attack/hit/death)
④ 3D 애니 → 2D 스프라이트시트    FrameCaster (브라우저, 무료)
⑤ 시트 조립                      기존 build_player_sheet.py 그대로
```

### 이게 문제를 없애는 이유

**동작이 모션캡처다.** Mixamo 애니메이션은 사람이 실제로 뛴 데이터다. 보폭·무릎
높이·팔 스윙·상체 기울기가 전부 물리적으로 맞다. 우리가 숫자로 지시할 필요가 없다.

**프레임 수를 마음대로 정한다.** FrameCaster 에서 6장이든 12장이든 뽑는다.
같은 사이클에서 균등하게 샘플링하므로 **간격이 자동으로 맞는다.**

**캐릭터 동일성이 100%다.** 같은 3D 모델을 돌려 찍는 것이라 프레임마다 다른
사람이 나올 수가 없다.

**애니 하나가 아니라 전부 나온다.** idle / run / back_run / attack / hit /
death 를 같은 리그에서 뽑는다. 지금 비어 있는 행 5개가 한 번에 채워진다.

**측면 뷰가 옵션에 있다.** FrameCaster 의 `Side Scroller` 퍼스펙티브가 우리가
쓰는 정측면이다. 4방향·8방향도 되므로 나중에 확장도 열린다.

## 2. 도구

| 단계 | 도구 | 비용 | 확인한 것 |
|---|---|---|---|
| 이미지→3D | [Meshy](https://www.meshy.ai/) 또는 [Tripo](https://www.tripo3d.ai/) | 무료 티어 있음 | 이미지 1장에서 텍스처 포함 3D 생성. Meshy 는 자동 리깅 + 600여 개 프리셋 애니도 자체 제공 |
| 리깅·애니 | [Mixamo](https://www.mixamo.com/) | 무료 (Adobe 계정) | 2026년 7월 기준 동작. 상업 이용 로열티 없음 |
| 3D→스프라이트 | [FrameCaster](https://patriciostar.itch.io/framecaster) | 무료, 브라우저 | FBX/GLB/GLTF 업로드 → 애니 선택 → Side Scroller → 프레임 수·크기·패딩·조명 설정 → PNG 시트 |

대안: [SpriteEx](https://xionworld.itch.io/spriteex) — 데스크톱 앱, 8방향 + 픽셀
팔레트 적용. Blender 불필요.

> ⚠️ **저는 이 도구들을 직접 돌려보지 못했습니다.** 위 내용은 각 제품 페이지와
> 검색 결과에 적힌 것입니다. 실제 품질은 돌려봐야 압니다.

## 3. 두 갈래 — 캐릭터를 지킬 것인가

### (가) 우리 캐릭터를 3D 로 만든다
```
gem_N2_c.png → Meshy/Tripo 로 3D 생성 → Mixamo 리깅 → 애니 → FrameCaster
```
디자인이 유지된다. 다만 **이미지 1장에서 만든 3D 는 뒷면·옆면을 AI 가 상상해서
채운다.** 후드 안쪽, 등의 화살통, 망토 뒷면이 어떻게 나올지 모른다.
측면 뷰만 쓰니까 그나마 유리하지만, 확인이 필요하다.

### (나) Mixamo 기본 캐릭터를 쓰고 색만 맞춘다
```
Mixamo 무료 캐릭터 중 후드/로브 계열 선택 → 애니 → FrameCaster → 색 보정
```
품질이 확실하다. 대신 **우리 캐릭터가 아니다.** 지금까지 잡은 디자인을 버린다.

**(가)를 먼저 시도하고, 3D 품질이 안 나오면 (나)로 내려가는 게 순서다.**

## 4. 실패하면 물러설 지점

3D 경로도 안 되면 남는 선택지:

**① 지금 6프레임으로 확정하고 넘어간다.** `2,3,5,6` + fps 7 은 진폭비 1.2배로
   나쁘지 않다. 뱀서류에서 플레이어 애니는 화면 중앙에 53×64px 로 나오고
   플레이어는 몰려오는 적을 본다. **완벽할 필요가 없는 부분이다.**

**② 애니메이션이 완성된 유료 에셋을 산다.** itch.io 에 측면 뷰 애니 세트가
   많다. 색만 우리 팔레트로 맞추면 된다. 몇 달러 수준이다.
