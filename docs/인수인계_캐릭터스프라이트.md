## 2. 확정된 값 — 바꾸지 말 것

### 캐릭터
- **C3** = 제미나이 생성 자마젠타 시안. 후드 궁수 + 등에 화살통 + 넝마 망토 + 큰 활
- 발광색 **`#e05cff`** (자마젠타, 색조 292도)
  - 이 색을 고른 이유: `main.js` 의 채도 있는 색을 색조 20도 단위로 세어보니
    **280~339도가 통째로 비어 있었다.** 회녹색 바닥(G−R +5.9)의 보색이라 대비도 최대다.
  - ❌ 시안 계열은 쓸 수 없다 — 냉기 199도 / 스킬발사체 189도 / 산탄사수 175도 / 궁수적 170도
- 실측 목표: 몸통 명도 **50~58** (바닥 40.9) · 국소 대비 **14 이상**

### 시트 규격 (`main.js` 와 일치, 바꾸면 코드 수정 필요)
```
셀 96×116 · 8열 × 7행 = 768×812
접지선 ANCHOR = 108      (main.js: CH - 10)
화면 표시 53×64px        (셀 96 × scale 0.55)
행: 0 idle / 1 run / 2 back_run / 3 attack / 4 multishot / 5 hit / 6 death
프레임: 4 / 8 / 8 / 6 / 6 / 3 / 8 = 43장
fps:  6 / 12 / 12 / 14 / 14 / 10 / 10
```

### 코드에 이미 반영된 것
```js
// main.js — 연기 오라 (테스트 페이지에서 1× 확대로 눈으로 맞춘 값)
SMOKE_COLOR = 0xe05cff   SMOKE_MAX = 18    SMOKE_RATE = 10
SMOKE_LIFE = 0.8         SMOKE_RISE = 20   SMOKE_ALPHA = 0.4   SMOKE_SIZE = 1.4

// main.js — 플레이어 텍스처만 LINEAR (적·엘리트는 NEAREST 유지)
tex.setFilter(Phaser.Textures.FilterMode.LINEAR)
```
- **연기는 스프라이트에 굽지 않는다.** 코드가 그린다(`updateSmokeAura`). 이유 3개:
  굽힌 연기는 얼어붙고 · 64px에서 실루엣을 먹고 · 횃불 불꽃도 같은 방식이다.
- **LINEAR 이유**: 플레이어만 유일하게 **축소**된다(0.55배). NEAREST 는 확대용 필터라
  축소에 쓰면 외곽이 반짝인다. 적(1.1배)·엘리트(1.2배)는 확대이므로 NEAREST 가 맞다.

## 3. 파이프라인 — 이미 돌아간다

```
tools/sprites/build_player_sheet.py     스트립 → 시트 조립 + 검증 리포트
tools/sprites/make_anim_test.py         단독 HTML 애니 테스트 (서버 불필요)
```

`player_strips/` 에 **정확한 파일명**으로 넣고 `build_player_sheet.py` 실행:
```
idle.png  run.png  backrun.png  attack.png  multishot.png  hit.png
death_a.png  death_b.png
```
> 부분 일치는 못 쓴다 — `run` 이 `backrun` 까지 잡아서 정확 일치로 고쳤다.

스크립트가 자동으로 하는 일:
1. **초록 언매팅** — 단순 임계값은 실패했다(얇은 활이 초록으로 남음)
2. **AI가 그린 바닥선 제거** — `no floor` 를 써도 매번 그려온다. 폭 60%↑ & 두께 ≤4px 행
3. **런렝스 프레임 분리** — 균등 분할 불가. AI는 간격을 못 맞춘다
4. **애니별 공통 배율** — 프레임마다 따로 맞추면 커졌다 작아진다
5. **발끝 y=108 정렬** — 단, 애니 단위 오프셋이라 공중 프레임의 높이 차가 보존된다
6. **발광색 보정** `#e05cff` 로 끌어올림 (실측이 탁하게 나온다)
7. **망토 밑단 발광 자동 부착** — 목표 **14.4%** 가 나오는 강도를 이분법으로 찾는다.
   AI가 밑단 발광을 3번 연속 빼먹었고, 스트립마다 있기도 없기도 해서 적응형으로 만들었다

## 4. ⛔ run 애니 3번 실패 — 반복하지 말 것

### 1차: 4프레임 + 4프레임으로 쪼개 요청
"후반부는 다리를 바꾼 같은 동작"이라고 했더니 **전반부를 그대로 재현**했다.
실측: 프레임별 실루엣 차이 **0.1~1.5%** (정상 변화량은 33~46%).
→ **쪼개지 말 것.** 한 이미지 안에 전체 사이클을 넣어야 프레임끼리 달라진다.

### 2차: 6프레임 한 장 + "세로로 두 번 오르내려라"
공중 프레임을 요구했더니 **"작게 점프해서 탁 떨어지는"** 결과가 나왔다.
→ 레퍼런스 8프레임 런사이클을 실측해서 원인을 찾았다:
```
보폭     0  24  26   0   0  23  36   0   ← 이게 변한다
발끝y   88  88  88  88  88  88  88  88   ← 전혀 안 움직인다
머리y   12  13  14  13  13  13  14  13   ← 2px, 몸높이의 3%
기울기 +4.4 ... +7.2                      ← 항상 앞으로
```
**발이 땅에서 떨어지지 않는다.** 달리기는 **보폭**으로 표현된다(0 → 몸높이의 48%).
세로 반동을 요구한 것 자체가 틀렸다.

### 3차: 상체를 안 적었다
프레임마다 **발 위치만** 적었다. 팔 스윙·상체 기울기·어깨 회전을 한 줄도 안 썼다.
게다가 `EXACT SAME character as the attached image` 라고 했는데 C3는 **서 있는 자세**라
모델이 의상뿐 아니라 **자세까지 유지**했다. 결과: 다리와 망토만 움직이는 서 있는 사람.

**구조적 문제도 하나 있다** — 발목까지 오는 넝마 망토가 다리를 덮어서 보폭이 안 보인다.
그리고 **활을 앞으로 뻗고 있으면 팔이 스윙할 수 없다.** 달릴 때는 활을 내려 들어야 한다.

### 4차(현재 대기) 요청문에 반영된 것
`docs/요청문/A1_run_8frames__attach_C3.txt` — 18개 항목 자동 검증 통과
- 8프레임 한 장, 프레임마다 **보폭 수치**(~0 / ~30% / ~50% / ~20%)
- `THE FEET NEVER LEAVE THE GROUND`, 머리 반동 3% 이내
- `CLEAR THE LEGS COMPLETELY` — 망토를 뒤·위로 젖혀 다리 노출
- 팔 90도 굽혀 다리와 **반대로** 펌프, 상체 전방 기울기(몸높이의 10%)
- 활은 **아래로 내려** 들기
- `STANDING POSTURE MUST NOT BE COPIED`
- 프레임 간격 40px, 바닥선 금지, 초록 `#00FF00` 배경

## 7. 미결정 사항

**attack·multishot 애니를 재생할지** — 현재 코드는 `idle`/`run`/`back_run`/`death` 만 재생한다.
`attack`·`multishot`·`hit` 은 `defs` 에 등록만 되어 있고 **호출하는 코드가 없다.**
재생하려면 두 문제를 풀어야 한다:
- 스프라이트 한 장이라 상하체 분리 불가 → 달리면서 쏘면 달리기가 끊긴다
- 기본 발사 간격 1.2초 vs attack 6프레임@14fps = 0.43초. 쿨감이 붙어 0.43초 아래로
  내려가면 애니가 끝나기 전에 재시작돼 덜덜 떤다

선택지: ① 재생 안 함(머즐·화살로 충분, 뱀서류에서 흔함) ② **멈춰 있을 때만 재생(권장)**
③ 무조건 재생하되 간격이 짧으면 건너뛰기

## 9. MCP — Claude Code CLI 에서만 된다 (2026-08-13 확인)

### Cowork(클라우드) 세션에서는 불가능하다 — 재확인하지 말 것
1. `.mcp.json` 은 **Claude Code CLI 전용 프로젝트 스코프** 설정이다. Cowork 세션은 읽지 않는다.
2. 우회로인 Gemini REST 직접 호출도 막힌다 — 클라우드 컨테이너 아웃바운드 allowlist 에
   `generativelanguage.googleapis.com` 이 없다 (curl → HTTP 000). npm 레지스트리는 200.
3. Cowork 의 사용자 PC 쪽 셸(`device_bash`)은 네트워크가 없어서 npx 실행도 안 된다.

### CLI 에서 MCP 붙이는 절차
```
PS> cd E:\claude\web-game
PS> claude
```
1. 온보딩(테마 선택)을 끝낸다.
2. 세션에서 `/mcp` 실행.
3. `nano-banana` 가 `⏸ Pending approval` 로 뜬다 → 선택해서 승인.
   (프로젝트 스코프 서버는 1회 승인이 필요하다. 승인 결과는 `~/.claude.json` 에 저장된다)
4. `✔ Connected` 및 도구 6개가 보이면 성공.

실패하면:
```
claude mcp list                    # 상태 일람
claude mcp get nano-banana         # 에러 상세
claude --debug=mcp                 # 디버그 로그 → %USERPROFILE%\.claude\debug\
cmd /c "npx -y nano-banana-mcp"    # 서버 단독 실행 (원인 그대로 보임)
claude mcp reset-project-choices   # 실수로 거절했을 때 되돌리기
```
npx 최초 다운로드가 30초 기본 타임아웃을 넘길 수 있다 → `$env:MCP_TIMEOUT="60000"; claude`

### ⚠️ 붙어도 안 될 수 있는 지점 2개 — 먼저 확인할 것
- **모델명이 낡았다.** 이 패키지는 `gemini-2.5-flash-image-preview` 를 호출한다.
  1년 가까이 갱신이 없었으므로 preview 모델이 은퇴했으면 404 가 난다.
  그러면 `mcp-nano-banana` `@easyuseai/nano-banana-pro-mcp` 등 최신 패키지로 갈아타면 된다.
- **API 키 형식.** `.mcp.json` 의 키가 `AQ.` 로 시작한다. AI Studio 표준 키는 `AIza` 로 시작한다.
  인증 실패가 나면 https://aistudio.google.com/app/apikey 에서 키를 다시 발급할 것.

**연결 확인용 첫 호출**: 프롬프트 한 줄짜리 아무 이미지나 생성해 본다.
스프라이트 요청문(토큰이 크다)을 첫 시도로 쓰지 말 것.

### 붙고 나면 달라지는 점
지금은 4단계다: 프롬프트 작성 → 사용자가 복사해 붙임 → 결과 저장 → 검증.
MCP 가 붙으면 **생성 → 슬라이스 → 실측 → 실패 시 프롬프트 수정 후 재생성**을
AI 가 직접 돌린다. run 애니처럼 "봐야 아는" 작업의 반복 비용이 크게 줄어든다.
