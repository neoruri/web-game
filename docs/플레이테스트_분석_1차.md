# 플레이 테스트 1차 — 피드백 원인 분석

> 2026-08-08 · 사용자 피드백 5건을 코드/수치로 검증했다. **분석만. 수정은 아직 안 함.**
> 결론부터: 5건 중 **3건이 같은 뿌리**에서 나온다 — **드랍·XP 총량이 통제되지 않는다.**

---

## 요약표

| # | 피드백 | 진짜 원인 | 심각도 |
|---|---|---|---|
| 1 | 레벨업 화면이 연속으로 뜬다 | XP 총량 폭주 → `_pendingLevels` 누적 | 중 |
| 2 | 에픽 룬 1개로는 체감 안 됨 | 3슬롯 **합산**이라 개별 룬이 희석 (17%뿐) | 중 |
| 3 | **무한 난사가 된다** | **지속시간(2.2s) > 쿨타임 하한(1.0s)** — 구조적 결함 | **높음** |
| 4 | 비교 화살표 도움 안 됨 | 종류가 5개뿐 + 합산이라 "더 좋다"가 의미 약함 | 낮음 |
| 5 | **10분에 룬 100개 이상** | 가방 상한 없음 + 킬 수 비례 드랍 | **높음** |

## 1. 무한 난사 — 가장 심각 (구조적 결함)

### 원인
난사는 **지속시간형** 스킬인데, **쿨타임이 지속시간보다 짧아질 수 있다.**

| 값 | 출처 |
|---|---|
| 난사 `baseCooldown` = **7초** | `skilltree.js` |
| 난사 `duration` = 1.5s(Lv1~3) → 1.8s(Lv4~7) → **2.2s(Lv8+)** | `skilltree.js` |
| 쿨타임 하한 `minSkillCooldown` = **1.0초** | `config.js` |

쿨타임 계산: `max(1.0, 7 × (1 - 쿨감룬) / (1 + 공속카드))`

```
쿨감룬 45%(캡) + 공속카드 12스택 → 쿨타임 1.96s  <  지속 2.2s  → ❌ 끊기지 않음
```
게다가 하한이 **1.0초**라 스택이 더 쌓이면 쿨타임 1.0s로 고정되는데
지속시간은 2.2s 그대로 → **영구 발동.**

### 핵심
**쿨감 캡(45%)만으로는 못 막는다.** 카드 패시브(공속 +8%/스택)가 캡 밖에서 곱해지기 때문.
`쿨감 룬 캡`과 `공속 카드`가 **서로 독립적으로 곱해지는 구조**가 근본 원인이다.

### 대응 후보
- (A) **지속시간형 스킬은 쿨타임 하한을 `duration + 여유(0.5s)`로** — 가장 확실
- (B) 공속 카드도 쿨감 총합 캡에 포함시켜 함께 clamp
- (C) 난사를 "지속시간" 대신 **발사 횟수**로 바꿔 무한 개념 자체를 제거
- ⚠️ (A)가 최소 변경이면서 원인을 정확히 막는다

## 2. 룬 100개 — 가방 상한이 없다

### 원인
`normalDropChance = 1%`가 **킬 수에 비례**한다. 그런데 10분이면 킬이 수천이다.

| 경과 | 누적 스폰(이론) | 처치율 60% 가정 | 1% 드랍 |
|---|---|---|---|
| 10분 | ≈ 7,785마리 | 킬 ≈ 4,670 | **룬 ≈ 47개** |
| (처치율 80%) | | 킬 ≈ 6,230 | **룬 ≈ 62개** |

실제 100개+ 보고는 처치율이 더 높거나 시간이 더 길었던 경우. **계산과 일치한다.**

### 왜 문제인가
- 가방 UI가 4열 그리드 → 100개면 **25행**. 스크롤로도 못 쓴다
- 앞서 "가방은 3~7개 수준"이라 예측했는데 **완전히 틀렸다.**
  그 예측은 "룬 7개/판"(보스 위주) 기준이었고, 일반몹 1% 드랍의 **킬 비례 폭증**을 놓쳤다

### 대응 후보
- **가방 상한(예: 12칸)** + 꽉 차면 가장 약한 룬 자동 폐기(또는 드랍 안 함)
- **드랍률을 시간 기반으로** — 킬 비례 대신 "N초마다 최대 1개"
- **하위 등급 필터** — 후반엔 일반 등급 드랍 안 함(레어+만)
- 드랍률 1% → **0.2~0.3%** 하향 (10분 기준 12~19개)
- ⚠️ 근본은 "킬 비례"라는 점. **시간 기반 또는 상한**이 정공법이다

## 3. 에픽이 체감 안 되는 이유 — 합산 희석

### 계산 (데미지 룬 평균: 일반 14% / 에픽 38.5%)
| 슬롯 구성 | 합계 | 피해 배율 |
|---|---|---|
| 일반 3개 | 42% | 1.42x |
| **에픽 1 + 일반 2** | 66.5% | **1.67x** |
| 에픽 3개 | 115.5% | 2.16x |

**일반 3개 → 에픽 1개로 교체 시 배율 변화는 1.17x — 약 17%뿐.**
여기에 카드 패시브(데미지 +10%/스택)까지 더해지면 희석이 더 심해진다.

### 즉 등급 범위가 좁은 게 아니라 **합산 구조가 개별 룬을 묻는다**
룬 하나가 전체의 1/3 미만 기여 → "에픽!"이라는 순간의 쾌감이 수치로 안 나타난다.

### 대응 후보
- **곱연산으로 전환** — 슬롯별 `×(1+v)`를 곱하면 에픽 하나의 영향이 커진다
- **에픽에 고유 효과 부여** — 수치만 큰 게 아니라 "에픽 화상은 전파" 같은 **질적 차이**
  (가장 체감이 큰 방식. 등급이 숫자가 아니라 성질이 된다)
- 등급 간 격차 확대(일반 10~18 / 에픽 50~70)
- ⚠️ 곱연산은 파워 폭발 위험 — 캡과 함께 가야 함

## 4. 레벨업이 연속으로 뜬다

### 원인
`xp.levelBase 5`, `levelGrowth 1.1` — 필요 XP가 완만히 증가하는데
**젬 1개 = 1XP**이고 10분에 수천 마리를 처치한다.

| 레벨 | 누적 필요 XP |
|---|---|
| Lv10 | 84 |
| Lv20 | 294 |
| Lv30 | 836 |
| Lv40 | 2,232 |

킬 수천 = XP 수천 → **레벨 40+까지 순식간.** `_pendingLevels`가 쌓여 화면이 연달아 뜬다.

### 대응 후보
- `levelGrowth` 1.1 → **1.18~1.25** (후반 레벨업 감속)
- **밀린 레벨업을 한 화면에서 처리** — "카드 3장 × 밀린 횟수"를 한 번에 고르게
- 레벨업 시 **일시정지 대신 짧은 슬로우모션**(뱀서 일부가 쓰는 방식)
- ⚠️ 지금은 화면이 뜰 때마다 게임이 멈춘다 → 연속이면 흐름이 완전히 끊긴다

## 5. 비교 화살표가 도움 안 됨

### 원인
- 룬이 **5종뿐**이라 "같은 종류 비교"가 걸리는 경우가 적다
- **합산 구조**라 "더 좋은 것으로 교체"의 이득이 미미(§3과 같은 뿌리)
- 100개 가방에서 화살표 몇 개는 노이즈에 묻힌다

### 대응 후보
- 화살표 대신 **"장착 시 DPS 변화"를 직접 표시**(이전 목업의 델타 프리뷰)
- 가방을 **등급·수치 순으로 자동 정렬** → 좋은 게 위로 오면 비교가 불필요해진다
- 아예 제거하고 **하위 룬 자동 숨김**(§2의 필터와 결합)

## 6. 뿌리는 하나 — "총량 통제 부재"

1·2·5번이 사실상 같은 문제다.

```
킬 수천 → XP 수천     → 레벨업 연속 (①)
킬 수천 → 룬 수십~백  → 가방 폭주  (⑤)
룬 많음 → 아무거나 채움 → 등급 무의미 (②④)
```

**드랍과 XP가 "킬 수"에 선형 비례하는데, 킬 수는 후반에 폭증한다.**
→ 후반 보상을 **시간 기반**이나 **상한**으로 바꾸지 않으면 어떤 UI를 만들어도 무너진다.

## 7. 권장 우선순위 (수정은 다음 단계)

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | **무한 난사 차단** (쿨타임 하한 ≥ 지속+0.5s) | 게임이 깨지는 버그. 최소 변경으로 해결 |
| 2 | **가방 상한 + 드랍 방식 변경** | UI가 실사용 불가 상태 |
| 3 | **레벨 성장 곡선 완화** (`levelGrowth` ↑) | 연속 레벨업으로 흐름 단절 |
| 4 | **에픽 차별화** (고유 효과 또는 곱연산) | 파밍 재미의 핵심인데 지금은 무의미 |
| 5 | 비교 화살표 → DPS 델타 or 자동정렬 | 4번을 고치면 자연히 개선될 수도 |

> 1~3은 **수치·소규모 로직**이라 시뮬로 검증 가능.
> 4는 설계 결정(합산 vs 곱연산, 에픽 고유효과)이 먼저 필요하다.
