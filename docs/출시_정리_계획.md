## 0. 먼저 — 왜 계속 수정만 하게 되는가

지금 흐름의 문제는 실력이나 속도가 아니다. **"완성"의 기준이 없다.**

이번 세션만 봐도:
```
룬 5종 → 8종 추가 → 슬롯 15칸인데 공급 2.5개라 안 채워짐
엘리트 4종 추가 → 초반 사망률 상승 → 첫 룬 보장 추가 → 설계 붕괴 → 철회
```
**기능을 추가하면 문제가 2~3개 생기고, 그걸 고치려 또 기능을 추가한다.**
빠져나오는 방법은 하나다 — **기능 동결 + 출시 기준선 확정.**

아래는 그 기준선 초안이다.

## 2. 가장 큰 문제 — 첫 30초가 도박이다

`CLAUDE.md`에 본인이 적어둔 원칙:
> **30초 룰** — 처음 30초에 재미 전달 못하면 이탈

그런데 시뮬 실측(400판):
```
룬 0개로 끝난 판 43% : 생존 중앙 29초 · 레벨 2 · 킬 9
룬 있는 판          : 생존 중앙 107초 · 레벨 15 · 킬 175
```

**한 판이 29초 아니면 107초로 갈린다.** 중간이 거의 없다(이분화).
즉 **10명 중 4명은 30초 안에 죽고 아무것도 못 본다.** 스킬도, 룬도, 엘리트도.

이게 지금 프로젝트의 **1순위 문제**다. 룬 종류를 늘리거나 원소를 추가해도
그 4명은 여전히 아무것도 못 본다.

### 방향 (수치 조정만, 코드 변경 최소)
- 첫 **20초는 스폰 간격을 1.5~2배**로 (숨 돌릴 시간 = 조작 익히는 시간)
- `spawn.rampPerMin 1.5` → 1.3 검토 (1분마다 1.5배는 초반 가속도 급하다)
- 첫 엘리트만 체력을 낮게 → **"엘리트를 잡아 룬을 얻는 경험"을 모두가 1회는 하게**
- ⚠️ 후반이 쉬워지면 안 되니 **초반만** 완화한다(`rampCap` 유지)

## 3. 잘라야 할 것 — 단순화

### ① 능력치 시스템 (힘/민첩/지능/활력) — **삭제**
`startAttrPoints: 0`, 코드 주석에 "미사용/보류". **값이 항상 0이다.**
튜너에서도 숨겼다. 그런데 `progression.js`의 `tierBonuses()`가 이걸 참조해서
계산 경로가 불필요하게 복잡하다.

> ⚠️ **그냥 지우면 안 된다.** `tierBonuses()`가 `critChance` `critDmg` `dodge`
> `regen` `dmgTakenMul` 같은 **실제로 쓰이는 값**을 만든다. 능력치 의존만 떼고
> **상수로 대체**해야 한다. (예: `critDmg: 1.5` 고정)

### ② 스킬트리 + 성장 화면 — **삭제**
```js
if (this.growthBtn) this.growthBtn.setVisible(false)   // 버튼이 숨겨져 있다
```
**플레이어가 접근할 수 없는 화면이다.** 관련 파일:
`growth-ui.js`(14KB) · `growth.css`(8.4KB) · `skilltree.html`

> ⚠️ `skilltree.js`의 `ACTIVE_SKILLS`(레벨별 `eff()`)는 **살아 있다.**
> 레벨업 카드가 이걸 쓴다. 파일을 지우지 말고 **트리 UI만** 뗀다.

### ③ 특화(SPECIALIZATIONS) — **보류 확정**
`chooseSpec()`은 연결돼 있지만 **선택할 UI가 성장 화면뿐**이라 도달 불가.
앞서 "원소를 특화로 주자"고 했는데, **선택 UI가 없으면 성립하지 않는다.**
→ 원소는 **출시 후**로 미루거나, 레벨업 카드에 넣는 방식으로 재설계.

### ④ 룬 슬롯 — **15칸 → 전역 3칸** (가장 중요한 단순화)

현재: 5스킬 × 3슬롯 = **15칸**, 공급은 판당 **2.5개** → 채움률 **17%**

```
지금:   "어느 스킬의 몇 번째 칸에 넣을까?"  ← 칸이 텅 비어서 고민이 없다
대안:   "3칸 중 무엇을 빼고 넣을까?"        ← 3개만 모아도 결정이 발생한다
```

**슬롯이 많은 게 깊이가 아니다.** 채울 게 없으면 그냥 빈칸이다.
전역 3칸이면 4번째 룬부터 **매번 교체 결정**이 생긴다 — 그게 파밍의 재미다.

| | 15칸(현재) | 전역 3칸 |
|---|---|---|
| 결정 발생 시점 | 16번째 룬부터 | **4번째 룬부터** |
| UI | 스킬 5행 × 3칸 스크롤 | 3칸 한 줄 |
| 잃는 것 | — | "폭발을 수류탄에" 같은 조합 재미 |

→ **조합 재미는 룬 종류가 20개쯤 될 때 의미가 생긴다.** 지금은 8종이고
공급이 2.5개다. **전역 3칸이 지금 규모에 맞다.**

### ⑤ 룬 8종 → **5~6종**으로 축소 검토
전역 3칸이 되면 종류가 많을수록 좋다(중복이 줄어서). 다만 **취약**은
"다른 스킬 피해까지 올린다"는 게 전역 슬롯에선 의미가 흐려진다 → 재검토 대상.

### ⑥ 보스 — **출시 v1에서 제외 검토**
엘리트와 역할이 겹친다(둘 다 룬 드랍). 컨셈도 재작업 예정이다.
**엘리트만 남기면** "24초마다 위협 + 룬"이라는 리듬이 단순해진다.
보스는 v2에서 "5분 생존 보상" 같은 명확한 역할을 갖고 돌아오는 게 낫다.

### ⑦ 배포 정리
- `lab.html` `tuner.html` `skilltree.html` — **개발 도구인데 Vercel에 배포된다.**
  빌드에서 제외하거나 `dev` 폴더로 분리
- `pasted-text.txt` 삭제 + `.gitignore` 추가
- `index.html` `<title>` 을 실제 게임 이름으로
- `player_spritesheet.png` **365KB** — 팔레트 축소/PNG 최적화로 절반 이하 가능

### ⑧ 유지 — 자르지 말 것
- **맵 다양화(이끼·구멍·깨진 타일·프롭·횃불)** — 이미 완성. 비용 다 냈다
- **엘리트 4종** — 이번 세션의 핵심 성과. 예고 패턴이 유일한 "실력" 요소
- **sim.js** — 개발 도구. 배포엔 안 나가고 밸런스 검증에 계속 필요

## 5. 그래서 올릴 수 있나

**지금 상태로는 아니다.** 무음 + 시작 화면 없음 + 43% 30초 이탈 —
이 셋 중 하나만 있어도 포털 심사나 재방문율에서 막힌다.

**하지만 남은 게 크지 않다.** 위 1~5번은 전부 **작은 작업**이고 새 시스템이 아니다.
게임의 뼈대(전투·성장·엘리트·결과 화면·맵)는 **이미 있다.**
지금 필요한 건 추가가 아니라 **덜어내기 + 마감**이다.

### 권장 순서
```
① 기능 동결 선언 — 위 "출시 후로 미루는 것"에 손대지 않는다
② 배포 정리 (§3-⑦) — 30분
③ 시작 화면 + 사운드 5종
④ 첫 30초 완화 → 시뮬로 "30초 내 사망률" 재측정
⑤ 룬 전역 3칸
⑥ 영구 해금 1개
⑦ 죽은 시스템 제거
⑧ 모바일 실기 테스트 → 출시
```

**④의 목표 수치를 미리 정해두자**: 30초 내 사망 **43% → 20% 이하**,
생존 중앙값 60~90초. 이 숫자를 만족하면 다음으로 넘어간다. 안 되면 멈춘다.
**기준을 정해놓지 않으면 또 무한히 만지게 된다.**
