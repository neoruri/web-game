# 변경내역 — 스킬별 발사 이펙트 + 에셋 교체

> 작성: 2026-08-06 · 최종 수정: 2026-08-07 · 기획·에셋 채팅(Cowork)에서 **직접 코드 반영함**
> 코드 채팅에서 이 파일을 먼저 읽고 이어서 작업할 것. (충돌 방지)

## ⚡ 2차 수정 (체감 개선) — 요약
1차 적용 후 **게임에서 이펙트가 거의 안 보이는 문제**가 있었다. 원인 진단:

| 원인 | 수치 |
|---|---|
| 화살이 자기 길이보다 빠름 | 속도 1200px/s = **프레임당 20px**. 연발 화살 길이는 12px → **끊긴 점처럼 보임** |
| 적이 붙어 있어 비행 시간이 없음 | 실제 비행 50~150px = **2~5프레임(42~83ms)** |
| 트레일 알파가 너무 낮음 | 0.13~0.22 + 질감 있는 바닥 → 사실상 안 보임 |

**해결**: ① **속도 비례 스트릭**(고정 길이 폐기) ② **알파 상향 + 글로우 레이어**
③ **머즐 플래시**(발사 지점에 머물러 가장 잘 읽힘). 아래 1-1·1-4·1-7에 반영됨.
- ⚠️ 화살 속도(`weapon.speed 1200`) 자체는 **변경하지 않았다**(조작감·밸런스 영향).
  더 필요하면 800~900으로 낮추는 걸 시뮬 검증 후 판단.

## 1. 코드 수정 — `src/main.js` (스킬별 발사체 이펙트)

**목표**: 스킬마다 화살이 다르게 보이도록. 룬 오버레이는 **미적용**(요청대로 기본만).
**성격**: 시각 전용. 데미지/관통/쿨타임 등 **게임 로직은 건드리지 않음** → `sim.js` 수정 불필요.

### 1-1. 상수 추가 (COLOR_SKILL_ARROW 아래)
```js
// trail: 'none' | 'thin' 얇은선 | 'dots' 점선 | 'fade' 페이드 잔상
// impact: 'spark' | 'flash' 섬광 | 'boom' 폭발(수류탄은 기존 링 사용)
const SKILL_FX = {
  basic:     { tint: 0xfab387, w: 2,   len: 10, trail: 'none', impact: 'spark' },
  multishot: { tint: 0x89dceb, w: 2,   len: 8,  trail: 'thin', impact: 'spark' },
  rapidfire: { tint: 0xf9e2af, w: 3,   len: 6,  trail: 'dots', impact: 'flash' },
  barrage:   { tint: 0xa6e3a1, w: 2.5, len: 15, trail: 'fade', impact: 'spark' },
  grenade:   { tint: 0xfab387, w: 3,   len: 10, trail: 'none', impact: 'boom'  },
}
const SKILL_FX_KEYS = Object.keys(SKILL_FX)
```
- `COLOR_SKILL_ARROW`는 **폴백용으로 남겨둠**(현재 렌더에선 미사용).
- ⚠️ 이 값은 `docs/skill_fx_preview.html`의 `LANES`와 **동일하게 유지**할 것(문서-코드 일치).

### 1-2. `fireAngle()` — 화살에 스킬 id 기록
```js
// 변경 전: a.skill = !!skill
a.fx = typeof skill === 'string' && SKILL_FX[skill] ? skill : skill ? 'multishot' : 'basic'
a.skill = a.fx !== 'basic'   // 기존 의미 유지(스킬 화살 여부)
```
- `skill` 인자가 **불린 → 스킬 id 문자열**로 확장됨. 문자열이 아니면 기존처럼 동작(하위 호환).

### 1-3. 호출부 — `true`/`false` 대신 스킬 id 전달
| 위치 | 변경 |
|---|---|
| `fireAt()` 기본 활 2곳 | `false` → `'basic'` |
| `triggerMultishot()` | `true` → `'multishot'` |
| 연발(rapidfire) 루프 | `true` → `'rapidfire'` |
| 난사(barrage) 루프 | `true` → `'barrage'` |

### 1-4. 렌더 루프 — 스킬별로 (트레일 → 본체) 묶어 스트로크
기존 2-pass(기본/스킬)를 **SKILL_FX 키별 루프**로 교체. 키마다 **트레일을 먼저 깔고 본체**를 그린다.
해당 화살이 없는 키는 패스를 건너뛴다.

```js
for (const key of SKILL_FX_KEYS) {
  const fx = SKILL_FX[key]
  // (1) 트레일 — fade는 2단계(px2→px1), thin은 1단계, dots는 뒤쪽 점 3개
  // (2) 본체 — lineStyle(fx.w, fx.tint) + 길이 fx.len
}
```

### 1-5. 트레일용 궤적 기록 (추가)
- `fireAngle()`에서 `a.px1/py1/px2/py2`를 현재 위치로 **초기화**(화살 풀 재사용 대비).
- `updateArrows()` 이동 직전에 `px2←px1`, `px1←현재위치`로 **2단계 밀어넣기**.
- 별도 배열/할당 없음 → GC 부담 없음.

### 1-6. 명중 이펙트 — `spawnSpark()` 확장
```js
spawnSpark(x, y, color = 0xffffff, style = 'spark')   // 기존 호출과 하위 호환
```
- `'spark'`: 기존과 동일한 짧은 직선, 단 **색이 그 스킬 색**으로 바뀜.
- `'flash'`: 더 짧고 굵은 **흰 섬광**(연발 전용) — 개수 3, 수명 짧음.
- 호출부(`updateArrows` 명중 지점):
  ```js
  const hfx = SKILL_FX[a.fx] || SKILL_FX.basic
  if (hfx.impact === 'flash') this.spawnSpark(a.x, a.y, 0xffffff, 'flash')
  else this.spawnSpark(a.x, a.y, hfx.tint, 'spark')
  ```
- 수류탄(`boom`)은 **기존 폭발 링 렌더를 그대로 사용**(중복 추가 안 함).

### 1-7. 머즐 플래시 (2차 추가)
- `this.muzzles = []` 배열 신규(생성자, `explosions` 옆). `updateMuzzles(dt)` 추가 후
  `updatePopups/updateParticles` 뒤에서 호출.
- `fireAngle()` 끝에서 발사 방향 12px 앞에 `{x,y,angle,r,tint,life:0.09}` push.
- 렌더: 스킬색 원 + 흰 코어 + 발사 방향 쐐기(모두 수명에 따라 축소·페이드).
- **왜 필요한가**: 화살은 2~5프레임만 존재하지만 머즐은 **0.09초 한 자리에 머물러**
  플레이어 시선 안에 확실히 들어온다. 빠른 투사체에서 스킬 구분 체감이 가장 큰 요소.

### 최종 적용 결과 (2차 수정 반영)
스트릭 길이 = `속도 × streak`. 1200px/s 기준 실제 픽셀 길이를 함께 표기.

| 스킬 | 색 | 굵기 | streak(초) → 길이 | 트레일 | 명중 | 머즐 |
|---|---|---|---|---|---|---|
| 기본 사격 | 주황 `0xfab387` | 2.5 | 0.032 → **38px** | 없음 | 주황 스파크 | 7 |
| 다발 사격 | 하늘 `0x89dceb` | 2 | 0.026 → **31px** | 얇은 꼬리 ×1.5 | 하늘 스파크 | 11 |
| 연발 사격 | 노랑 `0xf9e2af` | 3 | 0.022 → **26px** | 점 3개(간격 비례) | **흰 섬광** | 8 |
| 난사 | 민트 `0xa6e3a1` | 2.5 | 0.055 → **66px** | 페이드 꼬리 ×2.2 | 민트 스파크 | 9 |
| 수류탄 | 주황 `0xfab387` | 3 | 0.03 → 36px | 없음 | 기존 폭발 링 | 12 |

- 모든 스킬에 **글로우 레이어**(굵기 ×2.6, 알파 0.16)를 깔아 어두운 바닥 위 존재감 확보.
- 트레일 알파 상향: fade **0.34**, thin **0.26**, dots **0.5** (이전 0.13~0.35).
- 렌더 순서: 글로우 → 트레일 → 스트릭 본체 → (마지막에) 머즐 플래시.

### ⚠️ 스윕 충돌과의 상호작용 (중요)
코드 채팅에서 추가한 **스윕 충돌 판정**이 `a.px1/py1`(직전 위치)을 사용한다.
이 값은 **내가 추가한 코드가 갱신**한다:
- `fireAngle()`에서 `a.px1 = a.x`로 **초기화**(화살 풀 재사용 시 첫 프레임 오판 방지)
- `updateArrows()`에서 **이동 직전에** `a.px1 = a.x` 갱신 → 스윕 선분이 정확해짐
`px2`는 렌더가 속도 기반으로 바뀌어 불필요해져 **제거**했다. 이 순서를 바꾸면 충돌 판정이 깨진다.

### 검증
- `node --check src/main.js` **통과**
- SKILL_FX 키 ↔ 전달 id 일치 **통과**(누락 없음), `spawnSpark` 호출부 인자 호환 **확인**
- 성능: 최대 5키 × (트레일 ≤2패스 + 본체 1패스) = 화살 배열 순회 최대 15회/프레임.
  화살 200개여도 3천 회 수준으로 무시 가능. `dots`만 `fillCircle`을 쓰는데
  연발은 동시 화살이 적어 문제 없음.
- ⚠️ `npm run build`는 **리눅스 샌드박스에서 실행 불가**(node_modules가 Windows 바이너리).
  → **Windows에서 `npm run build` 한 번 돌려 확인 후 커밋**할 것.

### 남은 것 (원하면 다음 단계)
- **룬 오버레이**(화상=주황 잔상, 관통=화살 길어짐, 발사체+=개수↑)는 요청대로 **제외**.
  프리뷰(`skill_fx_preview.html`)에서 버튼으로 동작 예시를 볼 수 있고, 붙일 때는
  `SKILL_FX` 값에 룬 modifier를 곱하는 함수 하나만 추가하면 된다.

## 2-2b. 발사 위치 + 난사 조준 개선 — **코드 반영 완료 (main.js + sim.js)**

### 문제
1. 모든 화살이 **몸 중심 한 점**에서 나와, 특히 난사(360°)는 중앙에 뭉쳐
   "번쩍이기만 하고 날아가는 게 안 보이는" 상태였다.
2. 난사가 `Math.random() * 2π` — **완전 무작위 360°**라 화살 대부분이 허공으로 날아갔다.
   화려하지만 실제로 거의 안 맞음.

### 해결 1 — 발사 지점을 활/팔 위치로 (시각)
`SKILL_FX`에 **`spawn`**(발사 방향으로 밀어내는 px) 추가. `fireAngle()`에서 적용:
```js
a.x = this.player.x + cos(angle) * off
a.y = this.bowY     + sin(angle) * off * 0.55   // 아이소 2:1이라 세로는 눌러서
```
| 스킬 | spawn | 비고 |
|---|---|---|
| 기본 | 15 | |
| 다발 | 17 | 부채꼴이 벌어져 보임 |
| 연발 | 16 | |
| **난사** | **26** | 가장 크게 → 플레이어 주위 **링처럼** 퍼진다 |
| 수류탄 | 14 | |
- 머즐 플래시도 이 지점(`a.x/a.y`)에서 터지도록 변경(기존 +12px 중복 오프셋 제거).
- 난사 muzzle 크기는 9 → **6** (동시 발사가 많아 겹치면 과하게 밝아짐).

### 해결 2 — 난사 "적 방향 가중" (게임플레이) ⚠️ sim.js 동시 반영
`barrageAngle()` 신규 (main.js `fireAt` 위 / sim.js `updateBursts` 위, **동일 로직**):
- 사거리 **1.5배** 안의 적 중 **리저버 샘플링**으로 균등 무작위 1체 선택
  (가까운 적만 노리면 한 방향에 뭉치므로 의도적으로 무작위)
- 그 방향 **±`BARRAGE_JITTER`(0.45rad ≈ ±26°)** 로 흩뿌림
- 적이 없으면 기존처럼 완전 무작위(빈 화면에서도 발사 연출 유지)
- 배열 추가 할당 없음(리저버 샘플링) → GC 부담 없음

> ⚠️ `BARRAGE_JITTER`는 **main.js와 sim.js 양쪽에 각각 선언**되어 있다. 바꿀 때 둘 다 수정할 것.

### 시뮬 검증 결과 (120판, maxTime 300s)
| 지표 | 무작위 360°(이전) | **적 방향 가중(지금)** |
|---|---|---|
| 생존 중앙값 | 30s | **185s** |
| 평균 레벨 | 4.1 | **17.1** |
| 평균 킬 | — | 341 |
| 보스 처치 | 0.03 | **1.02** |

**난사 조준만 고쳐서 생존이 약 6배.** 그만큼 화살이 낭비되고 있었다는 뜻이고,
동시에 `밸런스_시뮬_리포트.md` §3의 "칼날 위 밸런스"가 재확인된다.

### ⚠️ 밸런스 후속 판단 필요
이제 **너무 강해졌을 가능성**이 있다. 조절 레버(강→약 순):
1. `BARRAGE_JITTER` 0.45 → 0.7~0.9 (더 흩뿌려 명중률↓, "난사" 느낌↑)
2. 난사 `barrageShots` / `damageMul` 하향
3. 적 압박 상향(`밸런스_시뮬_리포트.md` §4의 권장값은 이 변경 **이전** 기준이므로 재산정 필요)

## 2-2c. 버그 수정 2건 — **코드 반영 완료**

### 🐛 난사 꼬리가 캐릭터 반대편으로 뻗음
- **원인**: 스트릭/꼬리를 "속도 × 고정 시간"으로만 계산해, **발사 직후에도 최대 길이**로 그렸다.
  난사는 꼬리 끝이 `0.055 × 2.2 × 1200 = 145px` 뒤인데 발사점은 캐릭터에서 26px뿐 →
  **캐릭터 반대편 119px까지** 선이 뻗었다.
- **수정**: 화살에 `a.age`(발사 후 경과 초)를 기록하고(`fireAngle`에서 0, `updateArrows`에서 +dt),
  렌더에서 **글로우·꼬리·점선·본체 모두 `min(길이, a.age)`로 제한**.
  → 발사 직후엔 짧고, 날아가면서 자연스럽게 길어진다. 뒤로 넘치지 않는다.

### 🐛 횃불 불빛이 맵 이동 시 플레이어를 따라다님
- **원인**: `worldLayer.setPosition(W/2 - player.x, H/2 - player.y)` 이므로
  그 안의 `gfxArrows`는 **월드 좌표계**다. 그런데 `torchLights`에 **화면 좌표**를 저장해
  카메라 오프셋이 **이중 적용** → 불꽃이 화면에 붙어 따라다녔다.
  (바닥의 빛 고임은 캔버스에 직접 그려서 정상이었고, 흔들리는 불꽃만 어긋남)
- **수정**: 월드 좌표로 저장. `world = screen - center + player`
  ```js
  this.torchLights.push({ x: lx - W / 2 + px, y: ly - H / 2 + py })
  ```
  왕복 변환 검증 완료(화면→월드→화면이 원래 값과 일치).

> 💡 교훈: `worldLayer` 안에 그리는 것은 **전부 월드 좌표**, 바닥/전경 캔버스는 **화면 좌표**다.
> 두 좌표계를 섞을 때는 반드시 변환할 것.

## 2-3. 맵 다양화 (테스트 샘플) — **코드 반영 완료**

"맵이 단조롭다"에 대한 1·2단계 적용. 3단계(오브젝트·조명)는 미적용.

### 새 에셋 (`public/sprites/dungeon/`, 생성 스크립트 `gen_iso_extra.py`)
| 파일 | 내용 | 인덱스 규칙 |
|---|---|---|
| `tileset_iso_special.png` | 10칸 = **깨진 타일 6** + **구멍(void) 4** | `0~5` 깨짐 · `6~9` 구멍 |
| `tileset_iso_moss.png` | 16칸 = **이끼 대역**용 변형 | 기본 시트와 1:1 대응 |
- 규격 동일(셀 128×64, 가로 스트립, 알파). 미리보기 `_iso_extra_preview.png`
- 구멍 타일 = 거의 검정 + **위/좌 안쪽 테두리에만 빛** → "바닥이 없는" 깊이감.
- 이끼 팔레트는 석재와 **명도를 맞추고 초록으로만 살짝 기울임**(튀지 않게).

### `src/main.js` 변경
1. **로드**: `isospecial`, `isomoss` 추가. `floorSpecial`/`floorMoss`로 소스 이미지 보관.
   → 파일이 없으면 `spOk/mossOk`가 false가 되어 **기존 동작으로 자동 폴백**(안전).
2. **타일 선택(가중치)** — 좌표 해시 `hv % 100`으로 뽑는다:
   ```
   roll >= 97  → 구멍   (3%)
   roll >= 85  → 깨짐   (12%)
   그 외        → 일반 (85%) ← 이때만 대역 판정
   ```
   드물어야 특별해 보이므로 이 비율을 지키는 게 중요. 값은 `roll` 임계값만 바꾸면 조정됨.
3. **대역 블렌딩** — `isMossBiome(c, r, hv)` 신규:
   - **저주파 value noise**(셀 7타일, 바이리니어 + smoothstep)로 큰 덩어리 생성
   - 좌표 해시 기반이라 **스크롤해도 같은 자리는 같은 대역**(깜빡임 없음)
   - 경계 ±0.1 구간은 **디더링(확률 혼합)** → 직선 경계가 생기지 않음
   - 덩어리 크기는 `CELL`(현재 7), 대역 비율은 임계값 `0.55`로 조정

### 튜닝 포인트 (나중에 다듬을 때)
- 구멍이 너무 잦으면 `roll >= 97` → `98`. 깨짐은 `85` → `88` 등.
- 이끼 대역을 더 크게: `CELL` 7 → 10~12. 더 자주 나오게: `0.55` → `0.5`.
- 이끼 색을 더/덜 티나게: `gen_iso_extra.py`의 `PAL_MOSS`와 `tint [-5, 9, -4]`.
- ⚠️ 구멍은 **시각 전용**이다. 이동을 막거나 낙하 판정을 넣으려면 별도 충돌 로직 필요.

## 2-4. 오브젝트 레이어 + 횃불 조명 (3단계) — **코드 반영 완료**

맵 다양화 3단계. 정적 프롭을 배치해 공간감을 주고, 횃불로 국소 조명을 넣었다.

### 새 에셋
| 파일 | 내용 |
|---|---|
| `props_iso.png` | 셀 **96×112**, 8칸. 생성 스크립트 `gen_props.py` |
| 미리보기 | `_props_preview.png`(8종 전시) · `_props_ingame_preview.png`(실제 화면 재현) |

프레임 순서 = `0 무덤 · 1 기울어진무덤 · 2 석관 · 3 기둥 · 4 부러진기둥 · 5 부서진벽 · 6 횃불 · 7 잔해`
- **접지점은 셀 하단에서 10px 위**(`gen_props.py`의 `BASE_Y`). 코드의 `ANCHOR`와 반드시 일치시킬 것.
- 모든 프롭에 **바깥 밝은 림 + 접지 그림자** → 어두운 바닥에서 실루엣이 뜬다.

### `src/main.js` 변경
1. **로드**: `isoprops` 스프라이트시트(96×112). `propSheet`으로 소스 이미지 보관.
   파일 없으면 `drawProps`가 즉시 리턴 → **기존 동작 그대로 폴백**.
2. **전경 캔버스 신규**: `isopropfront`(depth **3**) — worldLayer(1)와 비네트(5) 사이.
3. **배치** `propAt(bc, br)`: `PROP_CELL`(=3) 타일마다 한 칸, **30% 확률**로 배치.
   칸 안에서 위치를 흩뿌려 격자 티를 없앤다. 좌표 해시라 **저장 데이터 불필요**.
   - 실측 밀도: **화면당 프롭 평균 7.1개 · 횃불 1.9개**(횃불 없는 화면 12%)
   - 종류 가중치: 횃불 32%(조명이 자주 보이게), 무덤류 25%, 기둥류 18%, 잔해 8%, 벽 10%, 석관 7%
4. **깊이 정렬** `drawProps()`:
   - 접지 y로 정렬 후, **플레이어 화면 y(=H/2) 기준**으로 분리
     → 위쪽(뒤)은 **바닥 캔버스**, 아래쪽(앞)은 **전경 캔버스**
   - 플레이어는 항상 화면 중앙이므로 이 비교가 곧 "앞/뒤" 판정이 된다.
   - **전경 프롭이 플레이어를 덮으면 `globalAlpha 0.4`** (디아블로/하데스 방식).
     안 하면 큰 오브젝트 뒤에서 캐릭터를 놓친다.
5. **횃불 조명 (2단 구성)**:
   - **바닥 빛 고임** — `lighter`(가산) 합성으로 따뜻한 방사 그라데이션. 바닥 캔버스에 그려지므로
     **플레이어가 움직일 때만 재계산**(비용 거의 없음).
   - **불꽃** — 매 프레임 `gfxArrows`에 그린다. 위치는 바닥 재그리기 때 수집한 `this.torchLights`.
     흔들림은 `sin(t*9 + 위상) + sin(t*23 …)` 2중 주기, **위치별로 위상이 달라** 같이 깜빡이지 않음.

### 튜닝 포인트
- 프롭 밀도: `PROP_CELL`(3 → 4면 절반) 또는 `h % 100 >= 30`의 30.
- 횃불 빈도: 가중치 `r < 83`(현재 32%) 조정.
- 빛 세기/범위: `drawProps` 안의 `createRadialGradient` 반경 118과 알파 0.30.
- 가려짐 반투명: `globalAlpha = 0.4`.
- ⚠️ 프롭은 **전부 시각 전용**이다. 충돌(밀어내기)이나 시야 차단은 별도 구현 필요.
