# 스프라이트 시트 — 시스템 · 형식 · 진행 과정 설명

이 문서는 "무엇을 만들어라"가 아니라, **스프라이트 시트가 어떤 시스템으로, 어떤 형식으로, 어떤 순서로 게임에 적용되는가**를 설명한다.
구체적인 캐릭터·컨셉·프레임 수는 이 원리를 이해한 뒤 게임 컨셉에 맞춰 결정하면 된다.

스택 기준: **Vite + Phaser 3.90 + Vanilla JavaScript**

---

## 1. 어떤 시스템으로 동작하는가

**스프라이트 시트 = 여러 장의 그림(프레임)을 한 이미지 파일에 격자로 담아둔 것.**
게임은 이 한 장에서 **한 번에 한 칸만 잘라 화면에 그리고**, 매 프레임 다음 칸으로 넘긴다. 빠르게 넘기면 그림이 움직이는 것처럼 보인다(만화책 넘기기와 같은 원리).

두 개의 시스템 층으로 나뉜다.

- **저수준(원리)**: `drawImage(이미지, 자를x, 자를y, 폭, 높이, 그릴x, 그릴y, 폭, 높이)` — 시트에서 특정 칸을 잘라 그리는 것. 순수 Canvas가 하는 일.
- **고수준(엔진)**: Phaser의 **애니메이션 시스템**. 위 자르기·넘기기를 개발자가 손으로 안 해도, "이 시트를 이렇게 잘라서 초당 N칸씩 반복 재생해라"라고 선언만 하면 엔진이 대신 처리한다.

즉 Phaser에서는 잘라 그리는 코드를 직접 짤 필요가 없고, **"시트 등록 → 애니메이션 정의 → 재생"** 3단계만 선언하면 된다.

---

## 2. 어떤 형식이어야 하는가 (에셋 규격)

시트 이미지가 지켜야 하는 형식:

- **파일 형식**: PNG (투명 배경 지원). JPG는 투명이 안 되므로 사용하지 않는다.
- **프레임 크기 일정**: 모든 칸이 동일한 가로×세로(`frameWidth × frameHeight`). Phaser는 이 크기로 시트를 자동 분할한다.
- **배치**: 프레임을 가로로 나란히(또는 여러 행으로) 격자 배치. 예) 한 칸이 200×100이고 6프레임이면 시트는 1200×100.
- **정렬**: 캐릭터를 각 칸의 중앙에 맞춘다(정렬이 어긋나면 재생 시 덜컹거림).
- **방향 통일**: 프레임 방향을 한쪽으로 통일(예: 전부 오른쪽). 반대 방향은 코드에서 좌우 반전으로 처리한다.
- **여백(선택)**: 칸 사이 간격이 있으면 로드할 때 `spacing`/`margin` 값을 함께 지정한다.

Phaser가 시트를 자를 때 참조하는 값은 결국 **frameWidth, frameHeight, (선택) spacing/margin** 뿐이다. 이 값이 실제 이미지와 정확히 일치해야 한다.

## 3. 어떤 순서로 진행되는가

| 단계 | 내용 | 담당 |
|---|---|---|
| ① 설계 | 프레임 수 · 프레임 크기 · 움직임 종류(회전/걷기/폭발 등)를 정함 | 기획 |
| ② 프레임 제작 | 조금씩 다른 그림 N장 생성 (AI 생성 / 코드 / 무료 에셋) | 에셋 |
| ③ 시트 패킹 | N장을 규격대로 한 장의 PNG로 합침 | 에셋 |
| ④ 프로젝트 배치 | Vite 정적 경로에 파일 배치 (`public/` → 코드에선 `public` 뺀 경로로 참조) | 프로젝트 |
| ⑤ 로드 (preload) | 시트를 불러오며 한 칸 크기를 지정 → 엔진이 N칸으로 자동 분할 | 코드 |
| ⑥ 정의·배치 (create) | 몇 번~몇 번 프레임을 초당 몇 칸으로 반복할지 애니메이션을 정의하고, 스프라이트를 화면에 배치해 재생 | 코드 |
| ⑦ 로직 연결 (update) | 이동·발사 등 로직과 위치를 연결. 필요 시 좌우 반전 | 코드 |
| ⑧ 확인 | 재생 여부 · 로드 에러(404) · 잘림 여부 점검 | 확인 |

②③은 에셋을 만드는 과정, ⑤⑥⑦은 Phaser 씬의 세 생명주기 함수(preload/create/update)에 그대로 대응한다.

---

## 4. Phaser 씬에서의 위치 (형식 대응)

스프라이트 시트 적용은 Phaser 씬의 세 함수에 나눠 들어간다. 각 함수가 "무엇을 하는 자리"인지가 형식의 핵심이다.

- **preload()** — 에셋을 불러오는 자리. 여기서 시트를 로드하고 **한 칸 크기(frameWidth/Height)** 를 알려준다. → 엔진이 시트를 프레임 번호(0,1,2…)로 나눠 관리하게 된다.
- **create()** — 한 번만 실행되는 설정 자리. 여기서 **애니메이션을 정의**(어떤 프레임 범위를, 초당 몇 칸, 반복 여부)하고, 스프라이트를 배치해 **재생 시작**한다.
- **update()** — 매 프레임 반복되는 로직 자리. **애니메이션 재생 자체는 엔진이 알아서** 돌리므로, 여기서는 이동·발사·방향 전환 같은 게임 로직만 처리한다.

핵심 개념 대응:
- "시트를 어떻게 자르나" → preload의 frameWidth/Height
- "몇 번 프레임을 얼마나 빠르게 반복하나" → create의 애니메이션 정의(프레임 범위 · frameRate · repeat)
- "언제 어디서 움직이나" → update의 로직

---

## 5. 원리를 벗어나면 안 되는 제약 (실패 지점)

- 프레임 크기가 제각각이면 자동 분할이 깨진다 → **크기 통일 필수**
- 로드 시 지정한 한 칸 크기가 실제와 다르면 **스프라이트가 잘려 보임**
- 프레임 번호 범위는 0부터 시작하므로 N프레임이면 마지막 번호는 **N-1**
- 파일 경로/이름이 틀리면 **404** (Vite에서는 `public` 폴더 기준 경로 규칙 확인)
- 애니메이션 "정의"만 하고 "재생" 호출을 안 하면 **움직이지 않음**

---

이 원리(시스템·형식·순서)를 기준으로, 게임 컨셉이 정해지면 대상·프레임 수·크기·애니메이션 종류만 채워 넣어 그대로 적용하면 된다.
