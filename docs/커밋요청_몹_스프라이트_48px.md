## 0. 한 줄 요약

`enemies_sheet.png` 를 **32px 셀에서 48px 셀로** 바꿨다.
**고블린과 사냥개 두 행**이 새 몹 그림으로 교체됐고, 궁수는 **그림 그대로**
새 셀에 옮겨 앉았다.

코드에서 고칠 곳은 **`load.spritesheet` 한 곳뿐**이다.

---

## 1. 교체된 파일 (이미 저장돼 있다)

```
public/sprites/dungeon/enemies_sheet.png        교체됨  128×96 → 192×144
public/sprites/dungeon/enemies_sheet_32_old.png 신규    이전 시트 백업
```

구성은 그대로다 — **4열(걷기 프레임) × 3행**, 피벗 `(0.5, 0.72)`.
행 의미도 그대로라 `e.type` 매핑을 안 건드린다.

```
행 0  (기본)      옛 고블린  →  붉은 뿔짐승     교체
행 1  (rusher)   옛 사냥개  →  붉은 랩터       교체
행 2  (shooter)  궁수                          그대로
```

## 2. 고칠 곳 — 딱 두 줄

`src/main.js:343` 근처.

### 지금
```js
// 적 스프라이트 (32×32, 3행[고블린/사냥개/궁수]×4프레임)
this.load.spritesheet('enemies', '/sprites/dungeon/enemies_sheet.png', {

```

### 이렇게
```js
// 적 스프라이트 (48×48, 3행[몹/사냥개/궁수]×4프레임)
// 셀을 32→48 로 올렸다. 새 몹 그림 원본이 400px 라 32px 로 담으면 12배 축소가 되어
// 뿔·발톱이 사라진다. 48px 면 화면 53px 에서 1.1배라 거의 원본 크기다.
this.load.spritesheet('enemies', '/sprites/dungeon/enemies_sheet.png', {
  frameWidth: 48,
  frameHeight: 48,
})
```

## 3. 건드리지 말 것 — `ENEMY_SPRITE_K` 는 그대로 0.11

```js
const ENEMY_SPRITE_K = 0.11   // 그대로 둔다
```

셀이 커졌는데 왜 안 바꾸나 — **궁수 그림을 원래 픽셀 크기 그대로**
48px 셀 안에 옮겨 담았기 때문이다. 셀 안 상대 위치가 안 바뀌었으므로 화면에서
지금과 똑같이 보인다.

```
32px 셀 피벗 y = 32 × 0.72 = 23.04
48px 셀 피벗 y = 48 × 0.72 = 34.56
차이 11.52  →  기존 그림을 (가로 +8, 세로 +12) 옮겨 붙였다
```

`ENEMY_SPRITE_K` 를 내리면 **궁수가 같이 작아진다.** 그건 원하는 게 아니다.

결과적으로 반지름 10 기준 화면 크기는:

```
행 0  뿔짐승   53px   (셀 48 × 1.1)             ← 커진다
행 1  랩터     53px                              ← 커진다
행 2  궁수     35px   (셀 안 그림이 32px 그대로)   ← 그대로
```

새 몹 둘이 궁수보다 큰 건 의도다. 크기로 종류가 구분된다.

> 튜너의 '크기' 슬라이더는 `enemy.radius` 를 움직인다. 반지름을 올리면
> 히트박스와 그림이 같이 커진다. 53px 은 기본값(r10)에서 나온 수치다.

## 4. 그 외 코드는 손대지 않는다

`updateSprites` 의 이 줄들은 셀 크기와 무관하다 — 그대로 둔다.

```js
spr = this.add.sprite(0, 0, 'enemies', 0).setOrigin(0.5, 0.72)
const row = e.type === 'rusher' ? 1 : e.type === 'shooter' ? 2 : 0
spr.setFrame(row * 4 + ((walk + e.animOff) & 3))
spr.setScale(e.r * ENEMY_SPRITE_K)
```

`row * 4 + (… & 3)` 은 **열 4개 / 행 3개**를 전제하는데 그건 안 바뀌었다.
`NEAREST` 필터 설정(`main.js:462`)도 그대로 둔다.

```
npm run build
```

게임을 띄워서:

1. **기본 몹이 뿔짐승, 돌격 몹(rusher)이 랩터로 바뀌었는가** — 안 바뀌면
   브라우저 캐시다. 강력 새로고침
2. **궁수가 예전과 같은 크기·위치인가** — 여기가 어긋나면 셀 옮기기가 틀린 것
3. **몹이 바닥에 붙어 있는가** — 떠 보이면 피벗(0.72) 문제

5. **뿔짐승과 랩터가 서로 구분되는가** — 둘 다 붉은 계열이라 섞일 수 있다.
   섞이면 한쪽 색조를 돌리거나 크기를 벌려야 한다

## 6. 이 그림이 어떻게 만들어졌나

조립은 `tools/sprites/apply_monster_sheet.py` 가 **전부** 한다. 시트를 손으로
고치지 말 것. 언제 돌려도 원본 스트립부터 다시 구워서 같은 결과가 나온다.

```
행 0  monster_strips/monster_walk.png    f3·f4 를 번갈아
행 1  monster_strips/monster2_walk.png   f1~f4 그대로
행 2  enemies_sheet_32_old.png           옛 궁수 그림을 (+8, +12) 이동
```

### 행 0 — 4장 중 2장만 쓴다
프레임별 보폭(앞발↔뒷발 ÷ 키) 실측:

```
f1   0    f2  39    f3  44    f4  31
```

`1,2,3,4` 로 돌리면 f2·f3 가 39·44 로 거의 같아 그 구간이 **정지처럼 보인다.**
`f3, f4` 를 번갈아(44 ↔ 31) 쓰는 쪽이 걸음이 산다. 시트에는 그 두 장을
`f3, f4, f3, f4` 로 네 칸에 채워뒀다 — 코드의 `& 3` 을 안 건드리려고 그렇게 했다.

꼬리는 **고정**이다. 꼬리만 떼어 ±8° / ±14° 회전시켜 위상을 만드는 것도 해봤는데
나란히 재생해보고 고정 쪽을 골랐다.

### 행 1 — 4장 다 쓰되, f4 는 갈아끼웠다
처음 받은 `monster2_walk.png` 는 4장 중 두 쌍이 사실상 같은 자세였다.
프레임 유사도(IoU) 실측 — 다른 쌍은 0.29~0.31 인데:

```
        받은 그대로        f4 교체 후
f2↔f4      0.77              0.38   ← 풀렸다
f1↔f3      0.61              0.64   ← 아직 남아 있다
```

`most_walk2-1.png` 의 f2 를 가져와 f4 자리에 넣었다(`splice_frames.py`).
보폭도 `38 / 99 / 27 / 101` → `38 / 98 / 28 / 78` 로 갈렸다.

> **f1↔f3 중복은 아직 안 풀렸다.** 걸음이 두 박자로 보일 수 있다.
> 나중에 f1 이나 f3 를 다른 생성본으로 갈아끼우면 된다. 이번 범위는 아니다.

### 조립 실측
```
행 0   접지 편차 0px   가장자리 침범 0개   키 40/44/40/44
행 1   접지 편차 0px   가장자리 침범 0개   키 42/36/42/42
행 2   접지 편차 2px   가장자리 침범 0개   ← 옛 그림 그대로라 원래 값이다
```

> 가로 배치는 **몸통 기준**이다. bbox 는 꼬리·뻗은 다리까지 포함하므로
> 그걸 기준으로 맞추면 **몸이 좌우로 튄다.** 플레이어 걷기에서 같은 실수를 했다.
>
> 셀 폭도 0.98 이 아니라 **0.92** 로 잡았다. 0.98 이면 반올림 때문에 꼬리·주둥이가
> 옆 칸을 1~2px 침범하고, 그러면 그 칸의 실측 접지까지 흔들려 검증을 못 믿게 된다.

## 7. 아직 안 된 것

```
궁수 그림           옛 픽셀아트 그대로다. 새 몹과 화풍이 다르다
행 1 f1↔f3 중복     걸음이 두 박자로 보인다 (위 참조)
피격/사망 프레임    없다. 지금은 tint 로만 표현한다
```

새 몹 둘은 음영이 많은 픽셀아트, 궁수는 납작한 도형 픽셀아트,
플레이어는 회화풍이다. **한 화면에 세 화풍이 섞인다.** 궁수도 같은 톤으로
다시 받는 게 다음 순서다. 이번 커밋 범위는 아니다.
