# 코드 요청 — 잡몹 시트를 48px 셀로 교체

> 대상: `E:\claude\web-game` code 채팅
> 작성 2026-08-20. 크기·프레임은 테스트 페이지에서 눈으로 확정한 값이다.

---

## 0. 한 줄 요약

`enemies_sheet.png` 를 **32px 셀에서 48px 셀로** 바꿨다. 고블린 행이 새 몹 그림으로
교체됐고, 사냥개·궁수는 **그림 그대로** 새 셀에 옮겨 앉았다.

코드에서 고칠 곳은 **`load.spritesheet` 한 곳뿐**이다.

---

## 1. 교체된 파일 (이미 저장돼 있다)

```
public/sprites/dungeon/enemies_sheet.png        교체됨  128×96 → 192×144
public/sprites/dungeon/enemies_sheet_32_old.png 신규    이전 시트 백업
```

구성은 그대로다 — **4열(걷기 프레임) × 3행(몹 / 사냥개 / 궁수)**, 피벗 `(0.5, 0.72)`.

---

## 2. 고칠 곳 — 딱 두 줄

`src/main.js:343` 근처.

### 지금
```js
// 적 스프라이트 (32×32, 3행[고블린/사냥개/궁수]×4프레임)
this.load.spritesheet('enemies', '/sprites/dungeon/enemies_sheet.png', {
  frameWidth: 32,
  frameHeight: 32,
})
```

### 이렇게
```js
// 적 스프라이트 (48×48, 3행[몹/사냥개/궁수]×4프레임)
// 셀을 32→48 로 올렸다. 새 몹 그림 원본이 400px 라 32px 로 담으면 12배 축소가 되어
// 뿔·발톱이 사라진다. 48px 면 화면 53px 에서 1.1배라 거의 원본 크기다.
this.load.spritesheet('enemies', '/sprites/dungeon/enemies_sheet.png', {
  frameWidth: 48,
  frameHeight: 48,
})
```

## 3. 건드리지 말 것 — `ENEMY_SPRITE_K` 는 그대로 0.11

```js
const ENEMY_SPRITE_K = 0.11   // 그대로 둔다
```

셀이 커졌는데 왜 안 바꾸나 — **사냥개·궁수 그림을 원래 픽셀 크기 그대로**
48px 셀 안에 옮겨 담았기 때문이다. 셀 안 상대 위치가 안 바뀌었으므로 화면에서
지금과 똑같이 보인다.

```
32px 셀 피벗 y = 32 × 0.72 = 23.04
48px 셀 피벗 y = 48 × 0.72 = 34.56
차이 11.52  →  기존 그림을 (가로 +8, 세로 +12) 옮겨 붙였다
```

`ENEMY_SPRITE_K` 를 내리면 **사냥개·궁수가 같이 작아진다.** 그건 원하는 게 아니다.

결과적으로 반지름 10 기준 화면 크기는:

```
새 몹      53px   (셀 48 × 1.1)          ← 커진다
사냥개     35px   (셀 안 그림이 32px 그대로)  ← 그대로
궁수       35px                            ← 그대로
```

새 몹이 다른 잡몹보다 큰 건 의도다. 크기로 종류가 구분된다.

> 튜너의 '크기' 슬라이더는 `enemy.radius` 를 움직인다. 반지름을 올리면
> 히트박스와 그림이 같이 커진다. 53px 은 기본값(r10)에서 나온 수치다.

## 4. 그 외 코드는 손대지 않는다

`updateSprites` 의 이 줄들은 셀 크기와 무관하다 — 그대로 둔다.

```js
spr = this.add.sprite(0, 0, 'enemies', 0).setOrigin(0.5, 0.72)
const row = e.type === 'rusher' ? 1 : e.type === 'shooter' ? 2 : 0
spr.setFrame(row * 4 + ((walk + e.animOff) & 3))
spr.setScale(e.r * ENEMY_SPRITE_K)
```

`row * 4 + (… & 3)` 은 **열 4개 / 행 3개**를 전제하는데 그건 안 바뀌었다.
`NEAREST` 필터 설정(`main.js:462`)도 그대로 둔다.

게임을 띄워서:

5. **몰려왔을 때 실루엣이 구분되는가**

## 6. 이 그림이 어떻게 만들어졌나

원본은 `tools/sprites/monster_strips/monster_walk.png` (1774×887, 4프레임).
조립은 `tools/sprites/apply_monster_sheet.py` 가 한다. 손으로 만지지 말 것.

### 4장 중 2장만 쓴다
프레임별 보폭(앞발↔뒷발 ÷ 키) 실측:

```
f1   0    f2  39    f3  44    f4  31
```

`1,2,3,4` 로 돌리면 f2·f3 가 39·44 로 거의 같아 그 구간이 **정지처럼 보인다.**
`f3, f4` 두 장을 번갈아(44 ↔ 31) 쓰는 쪽이 걸음이 산다. 시트에는 그 두 장을
`f3, f4, f3, f4` 로 네 칸에 채워뒀다 — 코드의 `& 3` 을 안 건드리려고 그렇게 했다.

### 꼬리는 고정
꼬리만 떼어 부착점 기준으로 ±8° / ±14° 회전시켜 위상을 만드는 것도 해봤다.
나란히 재생해보고 **고정 쪽을 골랐다.**

### 조립 실측
```
접지 편차 0px        네 칸 발끝이 모두 y=44
가장자리 잘림 0개     꼬리가 셀 밖으로 안 나간다
몸통 중심 편차 0.2px  ← bbox 중심이 아니라 몸통 기준으로 놓았다
```

> bbox 중심으로 놓으면 안 된다. bbox 는 꼬리·뻗은 다리까지 포함해서, 그걸
> 기준으로 맞추면 **몸이 좌우로 튄다.** 플레이어 걷기에서 같은 실수를 했다.

## 7. 아직 안 된 것

```
사냥개·궁수 그림      옛 픽셀아트 그대로다. 새 몹과 화풍이 다르다
피격/사망 프레임      없다. 지금은 tint 로만 표현한다
```

새 몹은 음영이 많은 픽셀아트, 사냥개·궁수는 납작한 도형 픽셀아트,
플레이어는 회화풍이다. **한 화면에 세 화풍이 섞인다.** 이 방향으로 갈 거면
사냥개·궁수도 같은 톤으로 다시 받아야 한다. 이번 커밋 범위는 아니다.
