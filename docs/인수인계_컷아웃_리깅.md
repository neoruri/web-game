> 다른 세션/다른 환경에서 이어서 작업하기 위한 문서.
> 최종 갱신: 2026-09-30

---

## 0. 왜 이 방식으로 왔는가

스프라이트 애니메이션을 AI로 **프레임 한 장씩** 만들던 것이 계속 실패했다.
프레임마다 캐릭터가 미묘하게 달라진다. LoRA 까지 학습시켜 겨우 잡았지만
`lora_final/run_f5` 는 끝까지 나머지와 달랐다. (경위: `docs/인수인계_캐릭터스프라이트.md`,
`docs/SD_run_실행결과_20260814.md`)

**컷아웃 리깅은 이 문제가 원리적으로 발생하지 않는다.**
그림 **한 장**을 파츠로 잘라 뼈로 움직이므로, 모든 프레임이 정의상 같은 그림이다.

핵심 안전장치가 하나 있다:

> **모든 회전 오프셋이 0이면 원본 그림과 픽셀 단위로 같아진다.**
> 즉 **절대 망가질 수 없는 바닥**이 있다. 검증도 이걸로 한다(rest 겹쳐보기).

## 3. ★ 피 흘려 얻은 규칙

**이 절이 이 문서의 핵심이다.** 각 항목은 여러 번 왕복한 끝에 나왔고,
전부 **육안으로는 놓쳤다가 수치·진단으로 잡은 것**들이다.

### 자르기

1. **폴리곤은 넉넉하게.** 배경이 검정이라 크리처 바깥은 어차피 투명이다.
   폴리곤은 **파츠끼리 나누는 역할만** 하면 되고 실루엣을 따라갈 필요가 없다.

2. **관절은 겹치게 자른다.** 한쪽만 가져가면 반대쪽에 홈이 남고, 조금만 돌려도 드러난다.

3. **단, 겹침은 관절 둘레에서만** (`JOINT_R`). 사방으로 넓히면 **옆을 지나는 다른 부위**까지
   길게 덮는다. 실제로 다리 주변에서 넓힌 30px 띠가 꼬리를 150px 넘게 덮어
   **꼬리가 두 개**로 보였다. 반경은 회전량으로 정한다 — 뼈가 θ 돌면 관절에서 d 떨어진 점이
   `d·sinθ` 어긋나므로, 그게 안 보일 크기여야 한다.
   - 팔(시전 26°) 110px / 꼬리(9°) 45px

4. **body 보다 뒤에 그려지는 파츠는 body 겹침이 필요 없다 (0).**
   뒤에 그려지면 body 가 앞에서 다 덮으니 틈이 안 보인다. 오히려 body 에 남은 복사본이
   파츠가 스윙할 때 **제자리에 남아 조각처럼 떠 보인다.**

5. **자식 파츠는 관절 아래에서 시작한다.** 관절 위를 물면 그 부분이 잘못된 축으로 돈다.
   실제로 정강이가 무릎 위 허벅지를 59% 삼켜서 **"허벅지는 안 움직이고 무릎만 꺾이는"**
   결과가 나왔다.

6. **다리는 부모를 앞에 그린다** (발 → 정강이 → 허벅지 순으로 쌓기).
   무릎 혹은 둥글어서 어떤 직선으로 잘라도 일부가 자식 쪽에 남는데,
   부모가 앞이면 진짜 혹이 그 잔재를 덮는다.
   겹치는 픽셀은 양쪽이 같은 원본 값이라 **순서를 바꿔도 쉬는 자세는 그대로**다.

7. **발광체(불꽃)는 알파 규칙이 다르다.** 기본 규칙은 불꽃 바깥의 **어두운 후광**까지
   불투명으로 만들어서, 잘라내면 검은 덩어리가 따라붙는다. 밝기로 서서히 투명해지게 해야 한다.

8. **부스러기는 걷어낸다** (`MIN_ISLAND = 600`). 단 **원본부터 떨어져 있는 그림**
   (불꽃의 불티 4개)은 예외로 둬야 한다. 그리고 **뭘 버렸는지 항상 출력한다.**

9. **가려진 파츠는 rest 검증으로 못 잡는다.** rest 겹쳐보기는 전체가 겹쳐 보이니
   치마 뒤 허벅지가 틀려도 똑같아 보인다. **파츠를 하나씩 띄워서 눈으로 확인할 것.**
   실제로 "왼쪽 허벅지는 가려서 그림이 없다"고 단정했다가 틀렸다 — body 를 따로 띄워보니
   근육 음영까지 있는 온전한 허벅지가 그대로 있었다.

10. **가는 부위는 격자를 촘촘히.** 100px 격자로 꼬리 좌표를 읽었다가 50px 어긋나
    **꼬리가 조각만 잘렸다.** 25~50px 격자로 다시 읽어야 한다.
    → 리거를 만든 이유가 이것이다. 마우스로 찍으면 이 종류가 통째로 사라진다.

### 움직임

11. **회전 오프셋만으로는 발을 땅에 못 붙인다.** 각 뼈를 사인파로 흔들었더니 발이
    접지선 위 35px(키의 9%)에 떠서 공중을 걸었다. 허벅지를 24° 돌리면 발끝은
    480px×sin24° = 196px 움직이는데 그게 전부 '위로' 갈 수 있다. → **IK 를 써야 한다.**

12. **3/4 뷰에서도 IK 가 된다.** "지면이 수평선이 아니다"라며 피했는데 과한 결론이었다.
    지면을 화면상 (거의) 수평선으로 근사하면 그만이고, 2D 컷아웃 리그는 다 그렇게 한다.

13. **쉬는 자세를 그대로 걷기에 쓰면 안 된다.** moster3 의 쉬는 자세는
    **버티고 선 런지**지 걷는 자세가 아니었다.
    - 왼쪽 다리 뻗은 정도 **97%** (직선 423 / 뼈합 436) → 여유 3%, 조금만 뒤로 뻗어도
      IK 가 한계에 걸려 다리가 막대기로 펴진다
    - 두 발 간격 415px(키의 38%), 엉덩이 간격은 160px

    → 걷기는 **자기 나름의 자세**를 쓴다. 발을 엉덩이 밑으로 모으고(`WALK_TOE`)
      골반을 낮춰(`WALK_CROUCH`) 여유를 만든다.

14. **키프레임은 rest 기준 오프셋이다.** 각도를 월드 기준으로 저장하므로, 폴리곤을 고쳐
    `rest` 가 바뀌면 저장값도 같이 옮겨야 한다. 안 하면 **캐릭터가 통째로 기울어버린다.**
    (리거 `anim.js` 의 `sync()` 가 처리)

15. **FK: 부모를 돌리면 자손도 같이 돌려야 한다.** 월드 각도 저장이라 자식 값이 안 변하는데,
    그대로 두면 부모를 돌릴 때 자식이 반대로 꺾인 것처럼 보인다.

16. **각도 차이는 -180~180 으로 정규화할 것.** 안 하면 ±180 을 넘는 프레임에서
    `-257°` 같은 값이 나와 진단을 잘못 읽는다.

## 4. 진단 — 읽는 법

### 자르기 (`cut_parts.py --check` 또는 리거 우측)

```
떨어진 조각    폴리곤이 놓쳤거나 남의 것을 물어온 흔적
               ⚠️ 원본부터 떨어진 그림(불티)은 오탐 — 좌표 보고 사람이 판단
중복 소유      두 파츠가 같은 픽셀 소유. 25% 초과면 다르게 움직일 때 둘로 보임
               ⚠️ 관절 근처의 겹침은 의도한 것(틈 메우기). 위치가 중요하다
```

### 움직임 (리거 동작 모드)

```
접지  되돌아감 N회      접지 중 x 가 되돌아가면 미끄러진다. 0 이어야 정상
굽힘  51~81° (30°)     변동 60° 넘으면 다리가 고무처럼 보인다
뻗음  1.00 한계         0.94 넘으면 IK 클램프 → 다리가 막대기가 된다
발끝 궤적               닫힌 고리. 아랫변이 지면 위 직선이면 안 미끄러진다
```

> **정지 이미지로는 미끄러짐을 절대 못 본다.** 궤적이나 수치를 봐야 한다.

## 5. 실행 방법

```bash
npm run dev
# http://localhost:5173/rigger.html     ← 새 크리처 작업
# http://localhost:5173/creature.html   ← moster3 확인
# http://localhost:5173/rig.html        ← 사람형 달리기
```

### 리거로 새 크리처 만들기

원본은 **배경이 순수 검정**이어야 한다.

```
1  이미지를 캔버스에 끌어다 놓기
2  [+ 추가] → [점 찍기] 로 외곽 클릭 (3점 이상, 넉넉하게)
3  [관절 놓기] → 회전 중심 클릭   ← 빼먹기 쉬움
4  [방향점] — 머리·손·꼬리처럼 자식 없는 끝 뼈만
5  부모 선택 · ↑↓ 로 앞뒤 조정
6  2~5 반복 (body 는 나머지를 자동으로 받으므로 안 그려도 됨)
7  [동작] 탭 → 접지 뼈(발) 지정 → 포즈 잡고 ◆ 키 찍기 → 재생
8  [내보내기] + [작업 저장]
```

화면 위 파란 안내줄이 **다음 할 일**을 계속 알려준다.

관절 위치: 머리=목, 상완=어깨, 전완=팔꿈치, 허벅지=엉덩이, 정강이=무릎.

### Python 파이프라인 (moster3 재생성)

```bash
cd tools/sprites/rig
<venv>/python.exe cut_parts.py --preview   # 폴리곤 확인 (필수)
<venv>/python.exe cut_parts.py --check     # 조각·중복 진단
<venv>/python.exe cut_parts.py             # 실제 자르기 + public/ 복사
<venv>/python.exe make_creature_rig.py     # 뼈 + 클립 + walk 진단
cd ../../.. && node tools/sprites/rig/shoot_creature.mjs   # 캡처
```

## 7. 남은 일 / 알려진 문제

### 다음 단계 후보

1. **게임 본편 적용** — `src/main.js` 의 몹 스폰에 `Rig` 연결.
   ⚠️ `main.js` 는 16만 자라 크다. 작업 전 범위를 좁힐 것.
2. **리거 2단계** — 걷기 자동 생성(IK + 슬라이더). 지금은 Python 으로만 가능.
3. **다른 크리처 적용** — `creatures_v4` 6종. 절차가 확립돼서 마리당 훨씬 빠르다.
4. **동작 추가** — hit / death / 이동

### 알려진 문제

- **왼쪽 다리 허벅지 그림이 얇다.** 치마가 많이 가린다. 보폭을 크게 키우면
  치마와 정강이 사이가 잠깐 비어 보일 수 있다. → `STRIDE` 를 줄이거나 폴리곤을 늘린다.
- **정강이 파츠 위쪽에 각진 조각이 남아 있다.** 지금은 허벅지가 앞에서 덮어 안 보이지만,
  무릎을 아주 크게 꺾는 동작(웅크리기·도약)에서는 삐져나올 수 있다.
  → 그때 폴리곤을 곡선으로 다듬는다 (리거에 `곡선으로 잇기` 있음).
- **부스러기 제거로 0.28% 가 빠진다.** rest 가 원본과 "완전 동일"은 아니다.
  겹쳐보기로는 구분이 안 되지만 정확히는 그렇다.
- **`src/rigger/img/` 에 테스트 산출물이 커밋돼 있다.** (`body.png`, `part1.png`,
  `*.rig.json`) 정리해도 된다.
