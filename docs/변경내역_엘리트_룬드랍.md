## 2. 엘리트 4종 — 설계 의도

각 패턴이 **플레이어에게 서로 다른 행동을 강제**하도록 골랐다.
능력치만 바꾸는 접두어(이속 1.6배 / 체력 3배)는 플레이어의 대응이 "계속 쏘기"로
똑같아서 다양성이 생기지 않는다.

| 엘리트 | 색 | 패턴 | 강제하는 행동 | 예고 모양 |
|---|---|---|---|---|
| **돌격자** | 붉은 | 예고 후 직선 고속 돌진 (관통) | **측면 회피** | 굵은 경로 띠 |
| **포격수** | 주황 | 플레이어 현재 위치에 착탄 원 | **자리 비우기** | 차오르는 원 + 십자 |
| **산탄사수** | 청록 | 부채꼴 다중 탄 5발 | **각도 이탈** | 부채꼴 라인 |
| **수호자** | 보라 | 주변 일반 적 강화(오라, 상시) | **우선순위 처치** | 바닥 오라 원 |

### 공통 규칙
- **반드시 예고 후 발동.** 예고 중에는 엘리트가 **멈춘다**(`e.windup`) → 읽고 대응할 틈
- **체력 4배 + 전용 체력바.** 체력바가 없으면 "단단하다"가 안 보여서 위협이 아니라
  답답함으로만 남는다. 엘리트에게 체력바는 선택이 아니라 필수
- **이름표** 표시 + 스프라이트 외곽 림을 패턴 색으로 → 작게 보여도 색으로 구분
- 예고 중 흰색 점멸

### 수호자가 가장 중요한 추가
지금 게임은 자동 조준이라 **표적 선택 판단이 전혀 없다.** 수호자는 오라 안의 적을
강화하므로 "저것부터 죽이면 편해진다"는 판단이 처음 생긴다.
오라는 **매 프레임 재수집**한다 — 수호자가 죽으면 강화가 즉시 풀려야 인과가 읽힌다(캐시 금지).

### 안전장치 (앞선 분석에서 지적한 함정들)
- 오라 이속 강화 후 속도를 **플레이어의 90%로 clamp** — 돌진형에 겹쳐 붙으면
  `70 × 1.35 = 94`로 플레이어(100)에 근접한다. clamp 없으면 회피 불가가 된다
- 엘리트·보스는 **오라 대상 제외** (엘리트끼리 서로 버프하면 폭주)
- 예고 발동 시 **시전자 생존 확인**(`indexOf >= 0`). 예고 중 죽으면 발동하지 않는다
- 텔레그래프 반환 시 `t.owner = null` — 풀에 죽은 적 참조를 남기지 않는다
- **`분열하는`은 채택하지 않았다.** 죽였는데 2마리가 나오면 **성공을 처벌**하는 셈이다.
  같은 맛이 필요하면 `소환사`(살아 있는 동안 부름 = 방치를 처벌)가 방향이 맞다

## 3. 룬 드랍 — 킬 비례 → 시간 기반

```
before: 일반몹 1% 드랍  → 킬 수천 → 룬 47~62개 (실측 100개+) → 가방 UI 사용 불가
after : 엘리트 확정 드랍 → 등장 주기 24s → 룬 2~7개
```

`config.rune.normalDropChance = 0` (경로는 남겨뒀지만 되돌리면 폭주가 재현된다)

**시뮬 실측** (150판 × 3가지 회피 실력 가정, 최대 10분):

| 회피 실패율 가정 | 생존 중앙 | 룬 평균 | 룬 최대 | 룬 0개 판 |
|---|---|---|---|---|
| 0.0 (완벽 회피) | 229s | 7.1 | 16 | 23% |
| 0.35 (기준) | 79s | **3.1** | 12 | 31% |
| 0.6 (자주 맞음) | 60s | 2.1 | 8 | 25% |

목표였던 "룬 3~5개"에 들어왔고, **최대치가 100개+ → 12개**로 잡혔다.

## 4. Lv3 첫 룬 보장 — 시뮬이 잡아낸 문제

엘리트 전용 드랍으로 바꾸니 후반 폭주는 잡혔지만 **초반에 급사한 판이 완전히
무보상**이 됐다(룬 0개 판 38~50%).

### 먼저 config로 고치려 했고, 실패했다
| 시도 | 결과 |
|---|---|
| 엘리트 첫 등장 30s → 18s | 룬 0판 38% → **49%** (악화) |
| + 동시 상한 2 | 53% (더 악화) |

**원인**: 엘리트를 일찍 부르면 그만큼 일찍 죽는다(생존 중앙 81s → 55s).
총 룬 수가 오히려 줄었다. → **config 값으로는 해결되지 않는 문제**였다.

### 그래서 전투 결과에 의존하지 않는 보장으로 해결
`onLevelUp()`에서 **Lv3 도달 시 룬이 하나도 없으면 1개 지급**.
→ 룬 0개 판 **38~50% → 23~31%**

### 남은 23~31%은 엘리트 탓이 아니다 (확인함)
400판을 분석했더니 **룬 0개 판 91건이 전부 Lv3 미달**이었다(91/91).

```
룬 0개 판 : 평균 생존 28.0s · 레벨 2.0 · 킬 8.6
룬 있는 판: 평균 생존 106.7s · 레벨 15.0 · 킬 174.9
```

이건 **기존의 "초반 급사 이분화"** 문제다(28s에 죽거나 107s를 산다).
보상으로 덮지 말고 **초반 스폰 압박을 따로 손대는 게** 맞다.
→ Lv2로 보장을 내리면 대부분 구제되지만, 시작 4초에 룬 모달이 뜨고
룬이 보상이 아니라 시작 아이템처럼 느껴진다. **일부러 안 했다.**

## 5. 강제 장착 제거 (사용자 지적 사항)

### 문제
룬 팝업에서 스킬을 **반드시 하나 탭해야** 화면이 닫혔다.
슬롯 3칸이 이미 좋은 룬으로 차 있어도 억지로 하나를 빼서 바꿔야 했다.

### 수정
- `rune-screen.js`에 **"가방에 넣기 (나중에 장착)"** 버튼 추가 → `onEquip(null, -1)`
- `main.js onRuneEquip()`이 `skillId == null`이면 **가방으로**(`isNew` 표시)
- 슬롯이 전부 찼으면 안내 문구가 바뀐다: "슬롯이 모두 찼습니다 — 바꿀 게 없으면 아래로 넘기세요"
- 스킬 행 설명도 "탭한 슬롯을 교체" → "바꿀 슬롯을 탭 **(안 바꿔도 됨)**"

버리는 게 아니라 가방에 남으므로 판단을 레벨업 화면으로 미룰 수 있다.

## 6. 함께 고친 버그 2건

### ① 교체된 룬이 조용히 사라지고 있었다
`onRuneEquip`에서 꽉 찬 슬롯에 장착하면 기존 룬을 **덮어써서 없어졌다**.
(가방 경유 장착인 `equipFromBag`은 정상적으로 가방으로 돌려보내고 있었다 — 두 경로가 달랐다)
→ 교체로 빠진 룬도 가방으로 보내도록 통일.

### ② 결과 화면의 '보스'가 등장 수를 표시하고 있었다
`bossCount`는 **스폰 시** 증가하는 값인데 결과 화면이 이걸 "보스 처치"로 표시했다.
보스를 못 잡아도 숫자가 올라갔다. → `bossKills`를 따로 세도록 분리.
(결과 화면 4번째 칸은 '엘리트'로 교체했지만 `bossKills`는 계속 전달한다)

## 7. 추가된 config (숫자만 — 문자열은 `withDefaults`가 무시한다)

```js
elite: {
  firstSec: 30, everySec: 24, maxAlive: 3,
  hpMul: 4, speedMul: 0.9, radius: 16, contactDamage: 14, gems: 5,
  knockbackResist: 0.4, attackInterval: 4.5, telegraphTime: 0.7,
  chargeSpeedMul: 4.2, chargeDur: 0.5, chargeDamage: 22,   // 돌격자
  shellRadius: 46, shellDamage: 18,                        // 포격수
  scatterCount: 5, scatterSpread: 0.3,
  scatterBoltSpeed: 200, scatterBoltDamage: 8,              // 산탄사수
  wardenRadius: 150, wardenSpeedMul: 1.35, wardenDamageMul: 1.4, // 수호자
}
rune: { normalDropChance: 0 }   // 0.01 → 0
```

튜너(SCHEMA)에 **'엘리트 · 등장·체력'** / **'엘리트 · 패턴'** 두 그룹 추가.

> ⚠️ 접두어 이름·색은 `main.js`의 `ELITE_KINDS` 상수에 있다.
> `config.js`에 넣으면 저장/복원에서 사라진다(`withDefaults`가 숫자만 복사).

## 8. 에셋

`public/sprites/dungeon/gen_elites.py` → `elites_sheet.png` (48×48, 4행×4프레임)
개별 스트립 `elite_charger.png` 등 4개, 미리보기 `_elites_preview.png`

**설계**: 몸통은 좁게(14px) 두고 **패턴별 장비가 실루엣을 지배**하게 했다.
1차 시도에서 금색 밴드를 넓게 써서 4종이 다 같아 보였고, 좁힌 뒤 구분이 살았다.
- 돌격자 = 뿔 + 대형 방패 (가로로 넓다)
- 포격수 = 위로 솟은 포신 (가장 높다)
- 산탄사수 = 부채꼴로 벌어진 볼트 + 고글
- 수호자 = 머리 위로 솟은 깃발 + 떠 있는 오브

외곽 림을 **패턴 색**으로 칠했다 — 작게 보여도 색만으로 어떤 위협인지 읽힌다.

재생성: `cd public/sprites/dungeon && python3 gen_elites.py` (numpy + Pillow)

## 9. sim.js 동기화

엘리트 스폰/드랍/오라/Lv3 보장을 모두 반영했다. 단 **패턴 피해는 근사**다:

```js
const ELITE_PATTERN_HIT = 0.35   // 봇이 예고를 못 피하는 비율 가정
```

봇은 예고를 보고 회피하는 판단을 못 하므로, 패턴을 그대로 재현하면 피해가
과대평가된다. 이 값이 **생존 중앙값을 208s ↔ 56s (3.7배)** 로 흔든다.
→ **시뮬 결과는 절대값이 아니라 설정 A/B 비교에만 쓸 것.**

### 두 파일에 중복된 값 (같이 고쳐야 함)
`RUNE_SLOTS` · 룬 등급 확률/범위 · `BARRAGE_JITTER` · 엘리트 스폰 로직 · Lv3 보장
