## 2. 엘리트 4종 — 설계 의도

각 패턴이 **플레이어에게 서로 다른 행동을 강제**하도록 골랐다.
능력치만 바꾸는 접두어(이속 1.6배 / 체력 3배)는 플레이어의 대응이 "계속 쏘기"로
똑같아서 다양성이 생기지 않는다.

| 엘리트 | 색 | 패턴 | 강제하는 행동 | 예고 모양 |
|---|---|---|---|---|
| **돌격자** | 붉은 | 예고 후 직선 고속 돌진 (관통) | **측면 회피** | 굵은 경로 띠 |
| **포격수** | 주황 | 플레이어 현재 위치에 착탄 원 | **자리 비우기** | 차오르는 원 + 십자 |
| **산탄사수** | 청록 | 부채꼴 다중 탄 5발 | **각도 이탈** | 부채꼴 라인 |
| **수호자** | 보라 | 주변 일반 적 강화(오라, 상시) | **우선순위 처치** | 바닥 오라 원 |

### 공통 규칙
- **반드시 예고 후 발동.** 예고 중에는 엘리트가 **멈춘다**(`e.windup`) → 읽고 대응할 틈
- **체력 4배 + 전용 체력바.** 체력바가 없으면 "단단하다"가 안 보여서 위협이 아니라
  답답함으로만 남는다. 엘리트에게 체력바는 선택이 아니라 필수
- **이름표** 표시 + 스프라이트 외곽 림을 패턴 색으로 → 작게 보여도 색으로 구분
- 예고 중 흰색 점멸

### 수호자가 가장 중요한 추가
지금 게임은 자동 조준이라 **표적 선택 판단이 전혀 없다.** 수호자는 오라 안의 적을
강화하므로 "저것부터 죽이면 편해진다"는 판단이 처음 생긴다.
오라는 **매 프레임 재수집**한다 — 수호자가 죽으면 강화가 즉시 풀려야 인과가 읽힌다(캐시 금지).

### 안전장치 (앞선 분석에서 지적한 함정들)
- 오라 이속 강화 후 속도를 **플레이어의 90%로 clamp** — 돌진형에 겹쳐 붙으면
  `70 × 1.35 = 94`로 플레이어(100)에 근접한다. clamp 없으면 회피 불가가 된다
- 엘리트·보스는 **오라 대상 제외** (엘리트끼리 서로 버프하면 폭주)
- 예고 발동 시 **시전자 생존 확인**(`indexOf >= 0`). 예고 중 죽으면 발동하지 않는다
- 텔레그래프 반환 시 `t.owner = null` — 풀에 죽은 적 참조를 남기지 않는다
- **`분열하는`은 채택하지 않았다.** 죽였는데 2마리가 나오면 **성공을 처벌**하는 셈이다.
  같은 맛이 필요하면 `소환사`(살아 있는 동안 부름 = 방치를 처벌)가 방향이 맞다

## 3. 룬 드랍 — 킬 비례 → 시간 기반

```
before: 일반몹 1% 드랍  → 킬 수천 → 룬 47~62개 (실측 100개+) → 가방 UI 사용 불가
after : 엘리트 확정 드랍 → 등장 주기 24s → 룬 2~7개
```

`config.rune.normalDropChance = 0` (경로는 남겨뒀지만 되돌리면 폭주가 재현된다)

**시뮬 실측** (150판 × 3가지 회피 실력 가정, 최대 10분):

| 회피 실패율 가정 | 생존 중앙 | 룬 평균 | 룬 최대 | 룬 0개 판 |
|---|---|---|---|---|
| 0.0 (완벽 회피) | 229s | 7.1 | 16 | 23% |
| 0.35 (기준) | 79s | **3.1** | 12 | 31% |
| 0.6 (자주 맞음) | 60s | 2.1 | 8 | 25% |

목표였던 "룬 3~5개"에 들어왔고, **최대치가 100개+ → 12개**로 잡혔다.

## 4. Lv3 첫 룬 보장 — 시뮬이 잡아낸 문제

엘리트 전용 드랍으로 바꾸니 후반 폭주는 잡혔지만 **초반에 급사한 판이 완전히
무보상**이 됐다(룬 0개 판 38~50%).

### 먼저 config로 고치려 했고, 실패했다
| 시도 | 결과 |
|---|---|
| 엘리트 첫 등장 30s → 18s | 룬 0판 38% → **49%** (악화) |
| + 동시 상한 2 | 53% (더 악화) |

**원인**: 엘리트를 일찍 부르면 그만큼 일찍 죽는다(생존 중앙 81s → 55s).
총 룬 수가 오히려 줄었다. → **config 값으로는 해결되지 않는 문제**였다.

### 그래서 전투 결과에 의존하지 않는 보장으로 해결
`onLevelUp()`에서 **Lv3 도달 시 룬이 하나도 없으면 1개 지급**.
→ 룬 0개 판 **38~50% → 23~31%**

### 남은 23~31%은 엘리트 탓이 아니다 (확인함)
400판을 분석했더니 **룬 0개 판 91건이 전부 Lv3 미달**이었다(91/91).

```
룬 0개 판 : 평균 생존 28.0s · 레벨 2.0 · 킬 8.6
룬 있는 판: 평균 생존 106.7s · 레벨 15.0 · 킬 174.9
```

이건 **기존의 "초반 급사 이분화"** 문제다(28s에 죽거나 107s를 산다).
보상으로 덮지 말고 **초반 스폰 압박을 따로 손대는 게** 맞다.
→ Lv2로 보장을 내리면 대부분 구제되지만, 시작 4초에 룬 모달이 뜨고
룬이 보상이 아니라 시작 아이템처럼 느껴진다. **일부러 안 했다.**

## 11. 🐛 일반몹이 여전히 룬을 드랍하던 원인 — **저장된 설정이 되살아났다**

`DEFAULTS.rune.normalDropChance` 를 `0.01 → 0` 으로 바꿨는데도 일반몹이 룬을
드랍했다. 코드에는 문제가 없었고, **localStorage** 가 원인이었다.

```js
// config.js withDefaults()
if (typeof v === 'number' && Number.isFinite(v)) out[group][field] = v
//  ↑ 저장된 숫자가 새 기본값을 **덮어쓴다**
```

브라우저의 `survivor.config.v4` 키에 예전 값 `0.01` 이 그대로 남아 있어서,
기본값을 0으로 바꿔도 매번 0.01 로 복원됐다.

### 수정
```js
const KEY = 'survivor.config.v5'   // v4 → v5
```
`config.js` 맨 위 주석에 이미 적혀 있던 규칙이었는데 지키지 않았다:
> "밸런스 기본값을 크게 바꿀 때 버전을 올리면 브라우저에 남은 옛 저장값을 무시한다"

**같은 구멍 하나 더 막았다** — 프리셋 A/B/C 키에는 버전이 없었다.
옛 프리셋을 불러오면 폐기한 값이 그대로 되살아난다.
```js
return `survivor.preset.${KEY}.${slot}`   // 프리셋도 버전을 따라가게
```

> ⚠️ **교훈**: "기본값을 0으로 끄는" 변경은 코드만 고쳐서는 적용되지 않는다.
> 반드시 `KEY` 버전을 올릴 것. (튜너에서 값을 한 번이라도 만졌으면 저장본이 생긴다)

## 12. 🐛 수류탄 2건

### ① 이미 죽은 자리에 던지던 문제

**원인**: `triggerGrenade` 가 `nearestEnemy()` 를 조준했다. 그런데 **기본 활도
같은 함수로 같은 적을 쏜다.** 화살은 1200px/s 로 즉시 도달하고, 수류탄은
`GRENADE_DUR 0.45초` 뒤에 도착한다 → 도착하면 그 적은 이미 죽어 있다.
광역 무기가 단일 표적을 따라가면 존재 의미가 없다.

**수정 3단**
1. **밀집 조준** — `bestGrenadeTarget()` 신규. 후보 적 주변 폭발 반경 안의
   적 수를 세어 **가장 밀집한 곳**을 노린다. 광역기의 정체성이 여기서 나온다.
   - 후보는 최대 14개만 샘플링(전수 조사는 O(n²)로 튄다). 소수 스트라이드(7919)로 골고루 훑음
2. **예측 사격** — 적은 플레이어 방향으로 오므로 `speed × 0.45초` 만큼 앞을 노린다
3. **착탄 보정** — 그래도 비었으면 `radius × 2` 안의 가장 가까운 적으로 스냅.
   ⚠️ 이 거리를 넓히면 광역기가 아니라 유도탄이 된다

### ② 2발 이상일 때 한 점에 뭉치던 문제

**원인**: 지터가 `(random-0.5) × radius × 1.1` = **±16px**(반경 30px 기준).
폭발 반경 30px 짜리 두 개가 16px 떨어져 있으면 거의 완전히 겹친다.

**수정**: 무작위 지터 → **링 배치**
```js
const ringR = st.radius * 1.15
const a = rot + (i / count) * Math.PI * 2
ox = Math.cos(a) * ringR
oy = Math.sin(a) * ringR * 0.62   // 아이소 뷰(2:1) 세로 압축
```
링 반지름 `radius × 1.15` → 인접 폭발 중심이 **약 2×radius** 벌어진다(겹치지 않음).
`rot` 은 매번 무작위라 패턴이 고정돼 보이지 않는다.

## 13. 룬 3종 추가 (5종 → 8종)

### 왜 이 3종인가 — "발사체 수와 곱해지지 않는" 것만 골랐다

다발 사격은 **최대 18발**까지 간다(Lv7+ 9발 + 특화 확산 +3 + 발사체 룬 +6).
여기에 **명중 시 새 히트를 만드는** 원소(번개 연쇄·폭발)를 붙이면
`18발 × 연쇄 6단 = 추가 히트 108회` 처럼 곱셈으로 폭증한다.

→ 그래서 **번개·폭발은 룬으로 넣지 않았다.** 그건 특화(`SPECIALIZATIONS`,
   이미 `SPEC_LEVEL = 5` 로 구현돼 있고 보류 상태)에서 **배타적 선택**으로 주는 게 맞다.
   배타적이면 "화염 다발 or 번개 다발"이 되어 곱셈이 구조적으로 막힌다.

| 룬 | 효과 | 중첩 | 어느 스킬과 맞나 |
|---|---|---|---|
| 🧪 **독** | `8~26%/초`, **최대 5중첩**, 4초 | **합산**(스택) | 히트가 많은 **다발·연발** — 빨리 최대 스택 |
| ❄️ **냉기** | 적 이속 `-12~40%`, 2.5초 | **최대값만** | 넓게 뿌리는 **난사** — 여러 적을 동시에 |
| 💢 **취약** | 받는 피해 `+10~32%`, 3초 | **최대값만** | 피해 낮은 **연발** — 디버프 거는 역할 |

### 설계 포인트

- **독은 화상과 규칙이 다르다.** 화상은 최대값만(중첩 X), 독은 중첩(O).
  같은 도트 2종이 기능적으로 겹치지 않게 갈랐다. 단 **스택 상한 5** 로
  "18발 = 18중첩"을 막았다. 스택당 dps 는 *가장 센 히트* 기준으로 유지한다
  (약한 히트가 스택을 희석하지 않게).
- **냉기는 상한 55%** (`RUNE_CHILL_CAP`). 없으면 적이 사실상 정지한다.
  수호자 오라 강화 **뒤에** 적용해서, 강화된 적도 늦출 수 있다.
- **취약이 가장 흥미로운 추가다.** 다른 스킬의 피해까지 올려주므로
  "피해가 약한 스킬로 디버프를 걸고 센 스킬로 때린다"는 역할 분담이 생긴다.
  단 **이번 히트에는 적용되지 않는다**(자기 자신을 증폭하면 안 됨) — 다음 히트부터.

### 구현 — `burn` 단일 인자 → `sfx` 묶음

`fireAngle(..., burn)` 이 상태이상 4종을 받아야 하는데 인자를 4개 늘리면 지저분하고,
화살마다 객체를 만들면 GC 부담이 크다(초당 수백 발).

→ `deriveStats()` 시점에 **한 번만** 만들고 발사체는 참조만 들고 다닌다:
```js
// progression.js
function makeSfx(agg) {
  if (!agg.burn && !agg.poison && !agg.chill && !agg.vuln) return null
  return { burn: agg.burn, poison: agg.poison, chill: agg.chill, vuln: agg.vuln }
}
s.weapon.sfx = makeSfx(bagg)   // 기본 활
st.sfx = makeSfx(agg)          // 스킬마다
```
재계산 전까지 불변이므로 안전하고, 할당이 0이다.
`damageEnemy(e, amount, dx, dy, sfx)` 가 숫자/true 도 받아서 하위 호환된다.

### 중첩 규칙을 한 곳에 명시
```js
// progression.js
const RUNE_MAX_ONLY = { burn: 1, chill: 1, vuln: 1 }   // 나머지는 합산
```
룬을 추가할 때 **어느 쪽인지 반드시 정해야** 한다. 이 표에 안 넣으면 합산이 된다.

### 시각 구분 (tint 우선순위)
```
피격(흰) > 화상(주황) > 독(연두) > 냉기(하늘) > 취약(분홍) > 수호자 강화(보라)
```
