# 컴팩트 기획 — MVP부터 시작해 키우기 (첫 웹 게임용)

앞의 `RUNE_SYSTEM_설계.md`는 **최종 목표(확장판)**. 이 문서는 **처음 출시용 최소 버전(MVP)**과
거기서 조금씩 늘려가는 로드맵이다. MVP는 "적게, 확실히 돌아가게"가 원칙.

---

## 0. 설계 원칙

- 시스템은 **두 개만**: ① 레벨업 카드(자주) ② 룬(보스, 드묾).
- MVP에선 **티어·색슬롯·합성·콤보 전부 제외**. 나중에 레이어로 추가.
- 스킬·룬 개수를 일부러 **적게** 시작 → 밸런스/구현이 쉬움.

---

## 1. MVP 범위 (이대로 먼저 구현)

### 스킬 (총 4개)
| 스킬 | 획득 | 동작 |
|------|------|------|
| 기본 사격 | 시작부터 보유 | 가장 가까운 적 자동 발사 |
| 다중 사격 | 카드로 해금 | 부채꼴 다발 발사 |
| 관통 사격 | 카드로 해금 | 관통하는 강한 화살 |
| 화살비 | 카드로 해금 | 지정 범위 낙하(광역) |

- 동시에 최대 **3개**까지만 활성(선택의 무게). 기본 사격은 항상 포함.

### 레벨업 카드 (XP로 레벨업 → 3장 중 1택)
카드 풀 = **스킬 해금/레벨 + 패시브** 만. 컴팩트하게.
- 스킬 카드: (미보유면) 해금 / (보유면) 레벨+1 → 데미지·발사체 등 기본 상승
- 패시브 카드(4종): 데미지 +10%, 이동속도 +8%, 최대체력 +15%, 공격속도(쿨감) +8%

### 룬 (총 5개, 티어 없음)
| 룬 | 효과 |
|----|------|
| 화상 | 명중 시 3초 도트 피해 |
| 관통 | 관통 +1 |
| 발사체 | 발사체 +1 |
| 데미지 | 그 스킬 피해 +20% |
| 쿨감 | 그 스킬 쿨타임 −15% |

- **슬롯: 스킬당 1개** (MVP는 딱 하나). 보스가 룬을 드랍하면 **끼울 스킬 1개 선택**.
- 이미 룬이 있으면 교체(기존 룬은 버리거나 보관 — MVP는 "보관 후 언제든 교체").

### 보스 / 드랍
- 일정 시간마다 보스 1마리 → 처치 시 **룬 3개 중 1개 선택**(획득) → 원하는 스킬에 장착.
- 일반 몹은 XP만 드랍(룬 X).

---

## 2. MVP 수치 (시작점, 단순)

```
스킬 최종피해 = 기본피해 * (1 + 데미지룬/패시브 합) 
쿨타임        = 기본쿨 * (1 - min(쿨감합, 0.6))     // 캡 60%만 유지
발사체수      = 기본 + 발사체룬/카드
관통          = 기본 + 관통룬
DPS(표시)     = 최종피해 * 발사체수 / 쿨타임
```
- MVP에서 지킬 **캡은 쿨감 60% 하나**면 충분. 나머진 자유 상승.
- 크리·치명피해는 **MVP 제외**(패시브 데미지로 대체) → 나중에 추가.

---

## 3. MVP UI (최소)

- **레벨업 화면**: 화면 정지 + 카드 3장(아이콘/이름/한줄 설명) 탭 선택. (뱀서류 표준)
- **룬 획득 화면**: 보스 처치 후 룬 3개 중 1개 탭 → "어느 스킬에?" 스킬 3버튼 → 끼움. 끝.
- 별도 인벤토리/필터/합성 화면 **없음**(보관 룬은 룬 획득창에서 "교체"로만).
- 스킬별 아이콘 밑에 **작은 룬 표식 1칸**만 표시하면 충분.

> 앞서 만든 풀 목업(`rune_equip_mockup.html`)의 슬롯·델타·콤보는 **2~3단계용**. MVP는 이보다 훨씬 단순.

## 4. 성장 로드맵 (출시 후 단계적 추가)

### 단계 1 — MVP (위 내용)
- 스킬 4, 룬 5, 슬롯 1, 티어 없음, 캡 1개. **먼저 이것만 완성·출시.**

### 단계 2 — 깊이 추가
- 슬롯을 **스킬 레벨로 1→2칸** 해금(카드가 슬롯 해금도 담당).
- 룬 **티어(T1~T3)** 도입 + 상위 보스가 상위 티어 드랍.
- 룬 5 → **8~9개**로 확장(분열·도탄·동결·독 등).
- 캡 추가: 치명확률(크리 도입 시), 연속발사.

### 단계 3 — 빌드 다양화
- **슬롯 타입(색)** 으로 몰빵 제한, 슬롯 최대 3.
- **시너지 콤보** 2~3종(화염폭발 등)부터 소량 도입.
- 룬 **합성(중복 3→상위 1)**, 보스별 **드랍 테이블** 분리.

### 단계 4 — 완성형
- `RUNE_SYSTEM_설계.md`의 전체 카탈로그·콤보·캡·스키마로 확장.
- 밴/리롤/락, 로드아웃 프리셋, 결정형 픽업(제단) 등 편의.

> 핵심: **각 단계가 그 자체로 완결**되게. 단계 2를 안 붙여도 단계 1로 게임이 성립해야 함.

---

## 5. 카드 vs 룬 역할 (혼동 방지, MVP에도 적용)

- **카드** = 어떤 스킬을 가질지 + 기본 강화 + 패시브. (자주, 영구)
- **룬** = 이미 가진 스킬에 특성 부여(화상 등) + 소폭 튜닝. (드묾, 교체 가능)
- 룬은 **새 스킬·패시브를 주지 않는다** → 카드 선택이 계속 의미 있음.

## 6. 최소 데이터 구조 (MVP)

```json
// 룬 (티어 없음)
{ "id":"burn", "name":"화상", "effect":{"dot_pct":0.10,"dur":3} }
{ "id":"dmg",  "name":"데미지","effect":{"dmg":0.20} }

// 스킬 상태 (슬롯 1)
{ "skill_id":"multishot", "level":2, "rune": "burn" }

// 플레이어 런 상태
{ "active_skills":["basic","multishot","pierce"],
  "passives":{"dmg":0.1,"movespeed":0.08},
  "rune_bag":["pierce","cdr"] }
```

## 7. 구현 순서 추천

1. 기본 사격 + XP/레벨업 3장 카드(스킬 해금/레벨 + 패시브)만 먼저.
2. 보스 스폰 + 룬 1개 드랍 + 스킬 1슬롯 장착.
3. 룬 5종 효과 연결(도트/관통/발사체/데미지/쿨감).
4. 여기까지가 **출시 가능한 MVP.** 이후 단계 2~4를 순서대로.
