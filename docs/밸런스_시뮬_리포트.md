# 밸런스 시뮬 리포트 (헤드리스 sim.js 분석)

> 분석일: 2026-08-06 · `src/sim.js` + `DEFAULTS`(config.js) 기준, 총 1,000+판 실행
> **주의**: sim.js 주석대로 봇은 최적 플레이를 못 한다(제자리 딜 위주). 따라서 **절대 생존시간은
> 사람보다 비관적**이다. 아래 결론은 ① 봇 실력과 무관한 **산술 검증**과 ② 설정 간 **상대 비교**에 근거한다.

## 1. 가장 큰 문제 — 룬 시스템이 사실상 도달 불가

500판 기준:

| 지표 | 값 |
|---|---|
| 생존시간 중앙값 | **34.6초** |
| 30초 내 사망 | **39%** |
| 60초 내 사망 | **67%** |
| 90초(첫 보스) 도달률 | **17.6%** |
| **보스를 1마리라도 잡은 판** | **3.4%** |
| 평균 레벨 | 6.5 |

`boss.everySec = 90`인데 중앙값이 35초 → **대부분 보스를 보지도 못하고 죽는다.**
방금 완성한 룬 MVP(5종)를 **플레이어의 96%가 경험하지 못한다**는 뜻.

> 봇이 약한 걸 감안해도, 보스 도달률이 낮다는 방향성은 유효. 사람 기준으로도
> "첫 보스=90초"는 MVP 콘텐츠를 뒤로 너무 미뤄둔 배치다.

## 2. 근본 원인 — 스폰이 처치를 산술적으로 압도 (봇 실력 무관)

기본 무기: `damage 20 / cooldown 1.2` → **16.7 DPS**, `pierce 1`(단일 타겟)
적 체력 30 → **처치 0.56마리/초**가 이론상 한계.

| 시점 | 스폰 | 처치(이론) | 적자 |
|---|---|---|---|
| 0초 | 1.43/s | 0.56/s | **2.6배** |
| 30초 | 1.75/s | 0.53/s | 3.3배 |
| 60초 | 2.14/s | 0.51/s | 4.2배 |
| 120초 | 3.21/s | 0.46/s | **7.0배** |

즉 **시작부터 적이 2.6배 빠르게 쌓이고, 시간이 갈수록 격차가 벌어진다.**
생존은 "카드/스킬로 얼마나 빨리 눈덩이를 굴리나"에 전적으로 달려 있고, 실패하면 30초 컷.

## 3. 밸런스가 "칼날 위"에 있다 (불안정·이분화)

`weapon.damage`만 바꿔본 결과 — 다른 값은 전부 고정:

| damage | 이론 킬/초 | 생존 중앙값 | 평균 | 보스킬 |
|---|---|---|---|---|
| 20 (현재) | 0.56 | 46s | 71s | 0.02 |
| 24 | 0.67 | 34s | 79s | 0.18 |
| 28 | 0.78 | 37s | 108s | 0.35 |
| **30** | 0.83 | **255s** | 205s | **0.93** |

**데미지 20→30(+50%)에 생존 중앙값이 46초 → 255초(5.5배).** 중앙값이 오르락내리락하는 건
결과가 **이분화(눈덩이 성공 vs 30초 즉사)** 됐다는 신호. 지금 세팅은 그 임계점 바로 아래에 있다.

다른 레버도 같은 절벽이 확인됨(각 80판):

| 변경 | 생존 중앙값 | 보스킬 |
|---|---|---|
| BASE | 30s | 0.03 |
| `spawn.baseInterval` 0.7 → **1.1** | **223s** | 0.84 |
| `enemy.hp` 30 → **20** | **178s** | 0.64 |
| `weapon.pierce` 1 → 3 | 47s | 0.34 |
| `weapon.cooldown` 1.2 → 0.8 | 39s | 0.13 |
| `boss.everySec` 90 → 45 | 32s | 0.34 |
| `xp.levelBase` 5 → 3 | 46s | 0.14 |

- **가장 효과적인 레버 = 스폰 간격, 적 체력, 기본 데미지** (관통·쿨감·경험치는 영향 작음)
- `boss.everySec`만 줄이면 보스는 자주 오지만 **생존이 안 늘어** 근본 해결이 아니다.

## 4. 권장 조치 (우선순위)

### 즉시 (룬을 실제로 경험하게)
1. **첫 보스를 앞으로**: `boss.everySec` 90 → **50~60초**. 이후 보스는 90초 간격 유지 가능
   (첫 보스만 앞당기는 별도 값 `firstBossSec`을 두는 것도 방법).
2. **초반 스폰 압박 완화**: `spawn.baseInterval` 0.7 → **0.9~1.0**, 또는
   `spawn.rampPerMin` 1.5 → **1.3**. (1.5는 분당 1.5배 = 매우 급하다)
3. **기본 처치력 상향**: `weapon.damage` 20 → **26~28** 또는 `enemy.hp` 30 → **24**.
   단, 30까지 올리면 과해짐(255초) → **26~28 구간에서 미세조정** 권장.

> 목표 지표: **생존 중앙값 60~90초**, **보스 처치 판 비율 50%+**, 클리어율은 낮게 유지.

### 그다음 (안정성)
4. **이분화 완화** — 초반 실패 구제 장치: 시작 시 잠깐 무적/스폰 유예(첫 10초 스폰 절반),
   또는 저레벨일 때 경험치 획득량 보정.
5. **관통 기본값 상향 검토** — 뱀서류는 다수 적 처리가 핵심. `pierce 1`은 단일 타겟이라
   군집에 무력하다. 기본 2로 올리면 체감이 크다(단독 효과는 작지만 다른 상향과 곱해짐).

### 확인 필요 (설계 판단)
6. **`MAX_ACTIVE = 5`** — 액티브가 4종인데 슬롯 5개라 결국 전부 열린다.
   `main.js:42`/`sim.js:49` 확정값. "스킬 선택의 무게"를 원하면 **3**으로, 다 열리게 둘 거면
   대신 스킬 레벨 상한·분기로 선택 압박을 만들 필요.
7. **쿨감 캡은 이미 안전** — `config.js`: `cdrCap 0.4`, `atkSpeedCap 0.75`,
   `minSkillCooldown 1`(하한 1초). 무한연사 위험 없음. **상태 문서에 이 캡을 명시**하면 좋다.

## 5. 재현 방법

```bash
# 기준선 (300판)
node -e "import('./src/sim.js').then(async m=>{const {DEFAULTS}=await import('./src/config.js');
  console.log(m.runBatch(DEFAULTS,300,{maxTime:480}))})"
```
- 스윕 스크립트 패턴: `DEFAULTS`를 clone → 값 하나만 변경 → `runBatch(c, N)` 비교.

## 6. 실제 플레이 UX 리뷰 (배포 사이트 직접 실행)

브라우저로 https://web-game-tau-sable.vercel.app 을 직접 실행해 관찰한 결과.

### 🔴 시각적 최우선 문제 — 캐릭터가 바닥에 묻힌다
- 어두운 후드 캐릭터 + 어두운 청회색 바닥 → **명도차가 거의 없어 캐릭터가 안 보인다.**
- 게다가 아이소 타일의 **검은 줄눈(그루트)이 캐릭터 뒤를 지나가** 실루엣을 끊는다.
- 조치안(택1 또는 조합):
  1. 캐릭터에 **외곽선/림라이트**(밝은 1~2px 테두리) 추가 — 가장 효과적
  2. 캐릭터 아래 **접지 그림자**를 더 진하게(띄워 보이게)
  3. 바닥 **줄눈 대비를 낮추고**(밝게) 타일 명도를 더 어둡게 → 엔티티가 위로 뜬다
  4. 캐릭터 스프라이트 배율 상향(`player.spriteScale 0.55`는 작다)

### 🟠 바닥 타일이 화면을 지배한다
- 내가 만든 아이소 타일이 **게임 스케일에서는 대비가 너무 강하다.** 다이아몬드가 크고
  줄눈이 굵어 "그물망"처럼 읽히며, 시선이 바닥에 먼저 간다.
- 조치: 타일 재생성 시 **줄눈 얇게/밝게**(`inset` 축소, GROUT 명도↑), 타일 자체 명도 약간↓.
  또는 타일 크기를 줄여 패턴을 잔잔하게. (`gen_iso_tiles.py`에서 조정)

### 🟠 적이 단순 원형 — 바닥과 디테일 불일치
- 적이 분홍색 단순 원(플레이스홀더)인데 바닥은 정교해서 **미술 톤이 어긋난다.**
- 적 종류(일반/돌진/원거리)가 **형태로 구분되지 않아** 위협 판단이 어렵다.
  → 최소한 색·크기·외곽선으로 종류를 구분할 것. (돌진형은 뾰족하게 등)

### 🟡 HUD 표기 (※ 의도된 보류 — 확인됨)
- 좌상단 `힘 0 민 0 지 0 활 0` = 룬 시스템 피벗으로 **의도적으로 보류/0 고정**한 기존 시스템.
  기획 의도이므로 버그 아님. 다만 **플레이어에게 보이는 화면에서는 숨기는 편**이 혼동이 없다
  (내부 확인용이면 디버그 모드에서만 표시).
- 하단 `내속도 100 · 적속도 50 · DMG 20`, `58 fps · 적 8` 도 같은 성격 →
  출시 시점엔 디버그 플래그로 감출 것.

### 🟢 좋았던 점
- **`다음 보스 85초`** 표기 — 다음 이벤트를 알려줘 목표감을 준다(유지 권장).
- 레벨업 카드 화면: 3장 배치·NEW/패시브 태그·아이콘 구성이 명확하다.
- 초기 로딩 빠르고 60fps 유지.

### ⚠️ 실측으로 §2 산술이 확인됨
플레이 22초 시점 HUD: **`Kills: 5`인데 화면의 살아있는 적 `27`.**
→ 스폰이 처치를 크게 앞지른다는 계산과 정확히 일치. (레벨 2, HP 이미 상당히 소모)

### 🔧 별건 발견 — 크롬 자동번역이 UI 텍스트를 깨뜨린다
크롬 자동번역이 켜진 채로 열면 한국어 UI가 **엉뚱하게 재번역**된다. 실측 예:

| 원본(소스) | 자동번역 후 화면 |
|---|---|
| 연발 사격 | **연발괜찮아** |
| 가까운 적을 단일 집중 연사 | **집중적으로 집중적으로 연사** |

- 소스(`main.js:32`)는 정상이므로 **게임 버그가 아니다.** 크롬이 페이지를 번역한 결과.
- 그러나 한국 사용자 상당수가 번역 기능을 켜두므로 **실사용 품질에 직접 영향**.
- 조치: `index.html`의 `<head>`에 아래를 넣어 번역을 차단할 것.
  ```html
  <meta name="google" content="notranslate">
  <!-- 또는 <html lang="ko" translate="no"> -->
  ```

## 7. 이번에 실제로 수정한 것 (에셋)

### ✅ 바닥 타일 재생성 — "그물망" 완화
`public/sprites/dungeon/gen_iso_tiles.py` 수정 후 `tileset_iso_stone.png` / `decals_iso.png` 재생성.
규격(128×64, 16종)은 그대로라 **코드 수정 없이 바로 반영**된다. 이전 파일은
`tileset_iso_stone_OLD.png`로 백업.

| 항목 | 이전 | 변경 |

### ✅ 적 스프라이트 3종 신규 — 실루엣으로 구분
`gen_enemies.py` → **`enemies_sheet.png`** (셀 **32×32**, 3행 × 4프레임, 알파)
개별 스트립: `enemy_goblin.png` / `enemy_hound.png` / `enemy_archer.png`
미리보기(실제 바닥 위): `_enemies_preview.png`

| 행 | 게임 타입 | 디자인 | 구분 포인트 |
|---|---|---|---|
| 0 | `normal` | **고블린** | 초록 · 직립 · 뾰족귀 · 몽둥이 |
| 1 | `rusher` | **사냥개** | 갈색 · **네발 가로 실루엣**(즉시 구분) · 붉은 눈 |
| 2 | `shooter` | **활 든 고블린** | 황토 후드 · **세로 활 실루엣** · 3~4프레임서 화살 장전 |

- 세 종이 **형태 자체가 달라** 색을 못 봐도 구분된다(색약 대응).
- 모든 스프라이트에 **어두운 라인 + 바깥 밝은 림**을 넣어 어두운 바닥에서 묻히지 않게 했다.
  → §6에서 지적한 "캐릭터가 바닥에 묻힘" 문제의 해법을 적에 먼저 적용한 것.
  **플레이어 스프라이트에도 같은 림 처리를 적용할 것을 권장.**

#### 코드 연결(코드 채팅에서 할 일)
```js
// 로드
this.load.spritesheet('enemies', '/sprites/dungeon/enemies_sheet.png',
  { frameWidth: 32, frameHeight: 32 })
// 타입 → 행 매핑
const ROW = { normal: 0, rusher: 1, shooter: 2 }
// 프레임 인덱스 = ROW[type] * 4 + (walkFrame % 4)
```
- 현재 적은 원(circle)으로 그려지고 있어(`COLOR_ENEMY/RUSHER/SHOOTER`), 이를 스프라이트로 교체.
- `enemy.radius 10`(지름 20) 대비 셀이 32이므로 **표시 배율 1.0~1.3** 정도가 적당.
- 보스는 아직 전용 스프라이트 없음 → 고블린을 1.8~2배 확대 + 색조 변경으로 임시 대응 가능.

## 8. 아직 못 한 것

- **장시간 플레이 관찰** — 자동화 세션에서 탭 rAF가 스로틀되어 게임 시계가 거의 멈췄다
  (10초에 1초 진행). 보스 등장·룬 획득 화면은 실제 플레이로는 확인하지 못했다.
  → 폰/PC에서 직접 플레이해 **룬 화면 흐름**을 확인하는 편이 정확하다.
- **빌드별 비교**(어떤 스킬/룬 조합이 지배적인가) — 현재 sim의 봇은 카드 선택이
  고정 전략(`botPickCard`)이라, 빌드 비교엔 전략 주입 옵션(`opts.pickCard`)이 필요하다.
