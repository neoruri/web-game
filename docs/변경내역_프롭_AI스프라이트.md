## 2. 파이프라인 (`tools/sprites/apply_props_n3.py`)

재현 가능하다. 다시 돌리면 같은 결과가 나온다.

1. **크로마키 — 언매팅.** 배경이 순수 `#FF00FF` 가 아니라 **8842종**(노이즈/압축)이었다.
   임계값으로 자르면 경계에 마젠타 프린지가 남으므로,
   `마젠타다움 = (R+B)/2 − G` 로 알파를 추정하고 `(px − (1−a)·BG) / a` 로 배경 성분을 뺐다.
   → **프린지 0px**
2. **8칸 분리** — 열 방향 런렝스. 8덩어리 검출 확인(assert).
3. **축소** — 공통 배율 `K = 0.30`, 셀을 넘는 프롭만 개별 축소.
   LANCZOS 2배 → BOX → UnsharpMask(1.0, 80, 3).
4. **정렬** — 가로 중앙, **bbox 하단을 y=111 에 맞춤**(기존 시트와 동일).
5. **톤** — 목표 명도 57 이 나오는 gamma 를 이분법으로 찾고(→ 1.2415),
   색조는 R−B / G−R 을 바닥 값으로 완전히 당김.

## 5. 작업 중 잡은 오류 (기록용)

### ① 배율을 기둥 기준으로 잡은 것 — 실패
AI 기둥은 434/173 = **2.51** 로 매우 슬림한데 기존 기둥은 112/75 = **1.49** 였다.
기둥을 셀 높이에 맞추니(K=0.251) 나머지 7종이 전부 작아졌다 — 무덤 45×71 (기존 75×81).
→ 공통 배율을 **나머지 7종 기준(K=0.30)** 으로 잡고 셀을 넘는 것만 개별 축소.
   실제로 기둥 하나만 걸린다.

### ② 횃불 화로가 코드와 8px 어긋남
`main.js` 는 `it.sy - 76` 에 광원과 불꽃을 그린다. 첫 배율에서 화로가 **68px** 위라
불꽃이 그릇에서 떠 있었다. 배율 수정으로 **77px** 이 되어 해결.
측정은 "최상단"이 아니라 **그릇 테두리**(상단 22px 중 최대폭 행)로 해야 맞다.

### ③ `match_props.py` 의 "따뜻한 픽셀 보호"를 이 소스에 쓰면 안 된다
그 스크립트는 `R−B > 25` 인 픽셀을 불꽃으로 보고 보호한다.
새 소스는 전체가 따뜻해서 **45.8%** 가 그 조건에 걸린다 — 절반을 보호해버린다.
애초에 보호가 불필요하다: 불꽃은 코드(`gfxFlames`)가 그리고 스프라이트의 장작은 그냥 어두운 나무다.

### ④ 후보 설계 오류 (1차)
`hue_pull` 을 gamma 와 같이 움직여서 "N1은 밝지만 색조가 안 맞고 N3은 색조는 맞지만 어둡다"가 됐다.
→ 색조는 항상 완전히 맞추고 밝기만 3단계로 나누도록 재설계.

### ⑤ 문서에 적었던 규격 두 개가 틀렸었다
- 접지선은 셀 맨 아래가 아니라 **y=102**(`ANCHOR = CH-10`). y=111 은 그림자 끝단이었다.
- 4번 칸은 "작은 제단"이 아니라 **부러진 기둥**(`pillar(broken=True)`). 확대 이미지 육안 판단이 틀렸다.

`docs/프롭_AI생성_프롬프트.md` 를 이 내용으로 수정했다.

## 6. 남은 사항

- **파일 크기 8.7KB → 60.1KB (+51KB).** 20MB 예산에는 영향 없다.
  팔레트 양자화를 재봤으나 32색까지 줄여도 51.5KB 로 **9KB 밖에 안 줄어든다** → 그대로 둔다.
- **백업 파일을 만들지 않았다.** `public/` 아래 파일은 Vite 가 `dist` 로 통째로 복사하므로
  `props_iso_OLD.png` 을 두면 그대로 배포된다(`tileset_iso_stone_OLD.png` 로 이미 겪음).
  이전 버전은 git 히스토리에 있다.
- 중간 산출물(`props_iso_N1~N3.png`, `_codex_props_*.png`, `_zoom_row_*.png`)은
  전부 `tools/sprites/` 에 있다 — `public/` 밖이므로 **배포**에는 포함되지 않는다.
  ⚠️ 단, **git 은 별개다.** `tools/sprites/` 는 gitignore 대상이 아니라서
  `git add .` 하면 미리보기·후보 PNG **15MB** 가 히스토리에 영구히 박힌다.
  → 커밋 전에 `.gitignore` 추가가 필요하다. `docs/커밋요청_바닥타일_프롭.md` 참고.
- **아트 일관성:** 새 프롭이 적 스프라이트(32×32)보다 훨씬 정밀하다.
  확대해서 보면 고블린이 상대적으로 납작하다. Poki 가 "통일된 아트 디렉션"을 요구하므로
  적 스프라이트도 같은 방식으로 다시 만드는 것을 검토할 만하다.
- **Windows 쪽에서 `npm run build` 확인 후 커밋** — 이 환경에서는 rolldown 이 Windows 네이티브라 빌드 불가.
