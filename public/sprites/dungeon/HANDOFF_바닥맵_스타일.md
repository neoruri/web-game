# 바닥/맵 렌더링 스타일 — 작업 인수인계 (Claude Code용)

> 목적: 탑다운 서바이버류 게임의 **바닥 맵 렌더링 스타일**을 정하기 위한 테스트를 진행했고,
> 최종적으로 **아이소메트릭(대각선) 불규칙 플래그스톤 + 데칼 레이어 + 위/아래 깊이 음영** 방식으로 결정했다.
> 이 문서는 그 과정과 최종안, 그리고 Claude Code로 넘길 샘플 파일을 정리한 것이다.

---

## 1. 핵심 결론 (먼저 읽기)

- **게임 로직은 평범한 탑다운 2D 그대로 둔다.** 이동/몬스터/발사체는 전부 월드 좌표에서 처리.
- **바닥 렌더링만** 아이소메트릭 다이아몬드 타일로 교체한다. (진짜 3D/원근 투영 아님)
- 리치한 던전 느낌(레퍼런스: *Under The Grave*)은 **한 장의 이미지가 아니라 여러 레이어**로 만든다:
  1. **바닥 타일 아틀라스** (다이아몬드 플래그스톤 변형 여러 개)
  2. **데칼 레이어** (크랙/이끼/웅덩이/잔돌을 랜덤하게 겹침)
  3. (선택) **오브젝트 레이어** (무덤/기둥/제단) — 아직 미구현
  4. (선택) **조명 레이어** (플레이어 횃불 등) — 아직 미구현
- 위/아래 가장자리에 **약한 어두움 그라데이션**을 얹어 깊이감을 준다.

## 2. 테스트한 스타일 (진행 기록)

| # | 스타일 | 방식 | 결과 |
|---|--------|------|------|
| A | 직선 격자 타일 바닥 | 축 정렬 타일을 스크롤 | 기본 동작 OK, 그러나 "직선만"이라 밋밋 |
| B | 불규칙 석재 (masonry) | 벽돌형 직사각 + 색/크랙/오염 | 색 통일·크랙·오염까지 다듬음. 여전히 직선 격자 |
| C | 핸드페인트 자갈 | Voronoi 셀 + 돔 셰이딩(쿠션형) | 손그림풍 청회색 표현 성공 (별도 스타일 옵션) |
| D | **유사 3D 원근 바닥 (Mode 7)** | 스캔라인 바닥 투영 | 원근은 그럴듯하나 **몬스터/발사체를 원근 공간에 다시 구현해야 함 → 기각** |
| **E** | **★ 아이소 불규칙 플래그스톤 + 데칼** | 대각선 다이아몬드 타일 + 데칼 겹침 | **최종 채택.** 탑다운 로직 유지, 대각선 + 타일별 변형 + 던전 톤 |

> D(Mode 7)를 잠깐 만들었지만, 사용자가 원한 건 "원근 투영"이 아니라 **레퍼런스처럼 대각선으로 깔린
> 바닥 타일이 조금씩 달라 보이는 것"**이었다. 그래서 최종은 E.

## 3. 최종안(E) 스펙

### 3.1 타일 아틀라스
- 파일: `tileset_iso_stone.png` — 가로 스트립, **16개 변형**, 각 타일 **128 × 64** (2:1 아이소 다이아몬드), 알파 포함.
- 팔레트(레퍼런스 *Under The Grave* 픽셀 분석값, 어두운 **청회색** R<G<B):
  - 하이라이트 `(92,108,124)` · 중간 `(46,55,66)` · 그림자 `(28,34,42)` · 그루트 `(11,13,18)`
- 각 타일 특징: 사인 노이즈로 **불규칙한 윤곽**, 얇은 그루트, 좌상단 광원 돔 셰이딩, 크랙/마모 얼룩/모서리 깨짐, 간혹 갈라진(2분할) 돌, 20% 확률 어두운(젖은) 돌.

### 3.2 데칼 레이어
- 파일: `decals_iso.png` — 가로 스트립, **8개**, 각 **64 × 64**, 알파.
- 종류: 크랙망 / 이끼(초록 저알파) / 웅덩이(어두운 청색) / 잔돌(rubble).
- 바닥 타일 위에 **드물게(예: 좌표해시 %5==0)** 겹쳐 그린다.

### 3.3 배치 공식 (핵심 코드)
```js
const TW=128, TH=64, N=16;                 // 타일 폭/높이/변형수
// 월드 원점의 화면 위치 (camX,camY = 카메라 월드좌표)
const ox = W/2 - camX, oy = H/2 - camY;
// 카메라의 그리드 중심 (역아이소 변환)
const cc = (camX/(TW/2) + camY/(TH/2)) / 2;
const rr = (camY/(TH/2) - camX/(TW/2)) / 2;
for (let r = rr-R; r <= rr+R; r++)
for (let c = cc-R; c <= cc+R; c++){
  const sx = ox + (c-r)*(TW/2) - TW/2;      // 다이아몬드 화면 좌표
  const sy = oy + (c+r)*(TH/2) - TH/2;
  const hv = hash(c,r);                     // 좌표 기반 결정론적 해시
  const k  = hv % N;                        // 변형 선택 (스크롤해도 고정)
  const flip = (hv>>8) & 1;                 // 좌우반전 → 변형 2배
  drawTile(k, flip, sx, sy);
  if (hv % 5 === 0) drawDecal((hv>>12)%8, sx+32, sy);  // 데칼 레이어
}
function hash(c,r){ return (((c*73856093)^(r*19349663))>>>0); }
```
- **포인트**: 변형/반전/데칼을 전부 `hash(c,r)`로 뽑으면 스크롤해도 각 타일이 일관되게 유지되면서
  "타일마다 조금씩 다름"이 나온다.

### 3.4 깊이 음영 (위/아래 어두움)
```js
// 상단
let gt=ctx.createLinearGradient(0,0,0,150);
gt.addColorStop(0,'rgba(6,8,12,0.55)'); gt.addColorStop(1,'rgba(6,8,12,0)');
ctx.fillStyle=gt; ctx.fillRect(0,0,W,150);
// 하단도 동일하게 (H-150 → H)
```

## 4. Claude Code로 넘길 샘플 파일

### 반드시 넘길 것 (최종안 E)
| 파일 | 용도 |
|------|------|
| `iso_topdown.html` | **최종 데모.** 아이소 바닥 + 데칼 + 위/아래 음영 + 탑다운 이동/몬스터/발사체. 단, 이미지가 base64로 **인라인**돼 있으니 실제 프로젝트에선 외부 PNG 로드로 바꾸는 게 좋다. |
| `tileset_iso_stone.png` | 바닥 타일 아틀라스 (16변형 × 128×64). |
| `decals_iso.png` | 데칼 레이어 (8종 × 64×64). |
| `gen_iso_tiles.py` | 위 두 PNG를 **생성하는 파이썬 스크립트**. 팔레트/불규칙도/크랙/데칼을 파라미터로 재생성·튜닝 가능. |

> `iso_topdown.html`은 배포 편의를 위해 PNG를 data URI로 박아 넣었다.
> Claude Code에서는 `tileset_iso_stone.png` / `decals_iso.png`를 **파일로 두고** `new Image().src='...'`로
> 로드하도록 바꾸면 된다. (인라인은 뷰어에서 상대경로 로드가 막히는 문제를 피하려던 것)

## 5. Claude Code에 줄 작업 지시(권장)

1. `iso_topdown.html`의 인라인 base64를 **외부 PNG 로드로 교체**하고, 바닥 렌더러(`isoFloor()`)를
   기존 게임 루프에 통합한다. (게임 로직은 건드리지 말 것 — 바닥 draw만 교체)
2. `gen_iso_tiles.py`로 타일을 재생성할 수 있게 파이프라인을 넣는다.
   튜닝 포인트: `N`(변형수), `inset`(그루트 두께), 팔레트 `ctrl_C`, 크랙/데칼 빈도.
3. 다음 단계(선택): **오브젝트 레이어**(무덤/기둥/제단 스프라이트)와 **플레이어 횃불 조명**을 추가하면
   레퍼런스(*Under The Grave*)에 더 근접한다. 오브젝트는 y좌표 기준 **깊이 정렬(z-sort)** 필요.

## 6. 알아둘 것 / 주의
- 타일은 알파가 있는 다이아몬드라, **틈(그루트)은 타일 뒤의 어두운 배경색이 비쳐** 만들어진다.
  배경을 그루트색(≈ `#0b0e13`)으로 깔아 둘 것.
- 다이아몬드가 서로 **꼭짓점에서 맞물려** 빈틈 없이 덮인다(2:1 비율 필수).
- 변형을 좌표해시로 고정하지 않으면 스크롤 시 타일이 **깜빡인다**. 반드시 `hash(c,r)` 사용.
- 성능: `drawImage`만 사용(픽셀 접근 X). 화면당 다이아몬드 수백 개 수준이라 60fps 여유.
